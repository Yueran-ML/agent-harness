# Columbina 第 2 阶段实施记录：会话日志、模型接入、工具管线、循环、无界面模式

> 本文写于项目还叫 Tack 的时候。项目在第 3 阶段期间改名为 Columbina，文中的名字、命令和路径已经换成新的，提交记录里保留旧名字。文中的测量数字是改名之前测得的。

**Goal:** 在第 1 阶段的内核之上，做出能跑通一个任务的最小 Agent：会话日志、模型接入、工具执行管线、Agent 循环和无界面的 `columbina run`。

**Architecture:** 只追加的会话日志是唯一的事实来源，模型看到的每条消息都先写进日志，每次请求都由日志导出。模型接入、工具管线和循环各是一组插件，经内核的服务和事件相连。循环把任务拆成回合和步，在四个拦截点上让别的插件改变走向。

**Tech Stack:** Python 3.11 及以上、asyncio、pydantic v2、PyYAML、httpx。开发工具是 uv、hatchling、ruff、pyright（严格模式）、pytest、pytest-asyncio、pytest-timeout、hypothesis、coverage。

设计依据是 `docs/plans/2026-10-09-columbina-design.md` 的第 5 到 8 节和第 12 节。这些章节已经按实现更新，各部件的精确语义以它们为准，本文不再重复。

## 与设计文档的差异

实现时有十二处与最初的设计不同。设计文档已按下面的内容更新。

1. 结束原因没有 `aborted`。被取消的调用没有结束分片。
2. 运行时让结束分片与到达的内容一致。没有内容的回复算 `EMPTY_RESPONSE`。
3. 日志里不存原始的分片流。`assistant/message` 存装配后的消息、用量和结束原因。
4. 事件的数据类就是事件的类型。插件用 `declare()` 登记自己的类型。
5. 投影是惰性的折叠，没有注册表服务。面向前端的注册表推到第 10 阶段。
6. 会话的持久化做在 `columbina.session` 里，由配置项 `root` 开启，没有单独的后端插件。
7. `minimal` 清单里的工具是只读的 `read`，不是 shell 工具。shell 工具要等权限和审批。
8. 工具管线里只有明确的 `Allow` 和 `Accept` 算放行。循环的两个决策点同样要求明确的决定。
9. 工具要求结束回合时，回合立即结束，排队的输入留给下一回合。
10. 新增模块 `columbina.cancellation`。它不在原设计里。模型运行时、工具管线和循环都要分清真取消和假取消，这个模块是从三处提炼出来的。
11. 重试的错误码多了 `STREAM_CLOSED`。
12. 新增 `render_requests`、变异检查工具和命令行参数 `--no-json`。

### Task 2: 内核注册表

**目的。** 给有名字的条目一个共用的容器。适配器、工具、Agent 和事件类型都用它。

**提交。** `6ffcd20`

**规模。** 源码新增 78 行，测试新增 104 行。新建的源文件：`src/columbina/kernel/registry.py`。

**要点。**

### Task 3: 模型服务

**目的。** 提供 `LLM` 服务。它按提供方的名字登记适配器，用 `call(request)` 发起一次调用。

**提交。** `98a9547`

**规模。** 源码新增 373 行，测试新增 596 行，文档和其余文件新增 8 行。新建的源文件：`src/columbina/llm/runtime.py`。

**要点。**

- 无论适配器做了什么，分片流都以恰好一个结束分片收尾。`LlmError`、意外异常、流中断、违反协议、空回复和流空闲，都变成带稳定错误码的错误结束分片。

- 适配器的流在结束分片送达之前关闭。读取方被取消或提前离开时也关闭。

### Task 8: 文件存储与单写者

**目的。** 把会话存成一个 JSON Lines 文件，同一时间只有一个写者。

**提交。** `69005ab`

**规模。** 源码新增 340 行，测试新增 488 行。新建的源文件：`src/columbina/session/lock.py`、`src/columbina/session/store.py`。

**要点。**

- 每条事件写出后立刻交给操作系统。`flush()` 是等数据落盘的屏障。新会话在第一条事件之前不落盘。
- 操作系统级的锁保证一个会话只有一个写者，同一进程内也一样。进程结束时锁自动释放。
- 写入或落盘失败一次后，文件不再接受写入，日志因此不会有洞。
- `read_session` 拒绝读不准的文件，并给出文件和行号。最后一行没有换行符说明进程写到一半就死了，这一行不读，续写时截掉。

**实测。** 检出 `69005ab` 后运行 `uv run coverage run -m pytest`：489 通过，3 跳过，覆盖率 100%（1915 条语句）。

### Task 11: 尾部修复、恢复与分叉

**目的。** 让停在回合中途的日志能够合上，并在此之上做恢复和分叉。

**提交。** `7e10314`、`d1bd8aa`

**规模。** 源码新增 189 行，测试新增 571 行。新建的源文件：`src/columbina/session/repair.py`。

**要点。**

- `closing_events` 读一份停在回合中途的日志，返回合上它要追加的事件：给每个没有结果的工具调用补结果，结束打开的步，结束回合。

- 性质测试允许监听器在取消的同时给出新输入。它随即发现清空 inbox 时会丢掉清空期间才给的任务。现在只丢弃开始清空时就在等的输入。
- 回放跳过顶替别的事件的消息。没有工具的请求写成 `no tools`，不再与名叫 `none` 的工具混淆。
- `read` 对要返回的行边读边解码，提示里的字符数与整行解码的结果一致。
- 变异检查先在原样的代码上跑一遍测试，并把没有测试运行的情况当作错误，不再算作发现了变异体。

**实测。** 检出 `ba35b2c` 后运行 `uv run coverage run -m pytest`：1049 通过，6 跳过，覆盖率 100%（3841 条语句）。
