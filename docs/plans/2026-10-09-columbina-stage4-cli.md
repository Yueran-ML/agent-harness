# Columbina 第 4 阶段实施计划：终端 CLI

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在终端里运行 `columbina` 就进入一个可以日常使用的交互界面：连续给任务，回复边生成边显示，工具调用看得见，需要点头的动作当场询问。

**Architecture:** 一个常驻的输入行拥有终端，由 `prompt_toolkit` 管理，其余内容都印在它上面。`rich` 只把要印的东西渲染成带转义序列的文本，不直接写终端。界面由会话事件驱动，流式分片只管还没写完的那一行。审批的应答者、会话内授权和斜杠命令各是一个小部件，经已有的服务相连。

**Tech Stack:** 增加两个运行依赖，`prompt_toolkit` 和 `rich`。两者在设计文档第 3.2 节已经列出。

## 先做的试验

写计划之前在本机做了三个试验，都经管道输入驱动，不需要终端。结论如下，脚本留在草稿目录里。

| 问题 | 结论 |
|---|---|
| 输入行开着的时候，别的协程印出的内容能不能出现在它上面 | 能。输入行被重画在新内容下面，用户已经打了一半的字还在 |
| 没写完的一行能不能作为提示的一部分画出来，并且随着内容增长重画 | 能。提示可以是一个函数，内容变了之后请求重画即可 |
| 一个输入行能不能既收任务、又收插话、又回答审批 | 能。按键绑定可以带条件，`y`、`a`、`n` 只在提问时生效 |
| 提问期间别的键怎么办 | 屏蔽不干净：回车、退格、方向键各有默认的绑定，通配的绑定压不过它们。改成提问时把用户打了一半的字收起来，换上一个空行，回答之后放回。别的键只会落进这个空行，提问结束时丢弃。试验里半行文字完好地回来了 |
| Ctrl+C 和 Ctrl+D 能不能由自己的绑定处理 | 能。有字时清空，没字时第二次才退出 |
| 状态行在测试里看不看得到 | 看不到。它要等终端回报光标位置才画，管道不会回报。状态行的文字因此单独测试，不经输入行 |
| `rich` 渲染出的带转义序列的文本能不能交给 `prompt_toolkit` 印出 | 能，经 `ANSI` 包装 |
| 没有控制台时怎么测试 | Windows 上默认的输出对象在没有控制台时直接抛错。测试要自己给出输入和输出对象，并放进一个应用会话里。给了之后 `patch_stdout` 也照常工作 |

## 设计决定

下面十二条是本阶段要定下来的事。每条给出决定和理由。

**1. 一个常驻的输入行拥有终端。** 交互期间始终有一个 `prompt_toolkit` 的输入行开着，别的内容都印在它上面。`rich` 把要印的东西渲染成文本，再交给 `prompt_toolkit` 印出。理由：两个库同时移动光标会互相打乱。输入行常驻，用户在 Agent 运行时才能打字。

**2. 流式文本按行落定。** 回复的文字一边到一边显示。已经完整的行印到输入行上面，没写完的那一行作为提示的一部分画出来，每来一段就重画。重画有节流，两次之间至少隔 50 毫秒。理由：印到上面的内容不能再改，所以只印不会再变的东西。

**3. 界面由会话事件驱动。** 工具调用、工具结果、回合的结束、重试，都取自 `session/event`。流式分片只用来显示正在生成的文字。一条回复的文字如果已经随分片印过，`assistant/message` 到达时只把剩下的半行落定，不重印。理由：续接的会话和实时的会话因此是同一种画法，界面不维护第二份状态。

**4. 一行输入的去向取决于 Agent 是否在忙。** 空闲时它是一个新任务，交给 `followup`。忙时它是插话，交给 `steer`，在最近的一步边界上被模型读到。以 `/` 开头的是命令。命令只在空闲时执行，忙时输入的命令不执行，并提示先按 Esc。理由：命令会改模型、权限和会话，在回合中途改这些东西的后果不好说清。

**5. Esc 停下当前回合，Ctrl+C 两次退出。** 忙时按 Esc 或 Ctrl+C，回合被取消，已经运行的命令连同它启动的进程被停下。空闲时 Ctrl+C 清空已输入的内容，输入为空时提示再按一次退出。Ctrl+D 在输入为空时退出。退出前当前回合照常收尾。

**6. 审批在输入行里问。** 问题印在上面：哪个工具，要动什么，为什么要问。命令和路径给出全文。提问期间，用户打了一半的字先收起来，输入行换成一行选项和一个空行。`y`、`a`、`n` 按下即生效，Esc 等于 `n`。别的键只会落进这个空行，提问结束时丢弃，收起来的字放回原处。同一时间只有一个问题。理由：设计第 9.5 节要求界面展示全文，只看开头没法对一条命令说"可以"。按键逐个屏蔽做不干净，试验见上表。

**7. "本会话都允许"是对这一次调用的原样授权。** 权限服务记下工具名和对象这一对，之后同一个工具对同一个对象的调用不再询问。它排在拒绝规则之后、询问规则之前。授权只存在内存里，进程结束就没了，续接的会话要重新问。对命令，只有拆分器看得懂时才有这个选项。审批接缝的结果仍然只有一次性的 `allowed-once`，授权是应答者在回答之前另行登记的。理由：授权的范围就是用户看到的那一条，不靠模式匹配，也就不会放宽到别的命令。看不懂的命令里可能有变量，同样的文字下一次做的事可以不同。

**8. 斜杠命令是一个服务。** `ctx.commands` 是命令的注册表。状态归谁，命令就由谁登记：权限的命令由权限一侧登记，会话的命令由会话一侧登记。命令返回要显示的文字，不产生模型消息。理由：设计第 11.5 节。以后的技能、压缩和待办各自带来命令，前端不必认识它们。

**9. 没有终端就不进交互界面。** 标准输入或标准输出不是终端时，`columbina` 以退出码 2 结束，并提示用 `columbina run`。前端从可选的终端服务取输入和输出，测试用这个服务换上管道输入和可读的输出。理由：交互界面在管道上的行为没有意义，悄悄退化成另一种模式会让脚本得到意料之外的结果。

**10. 续接是一个启动参数。** `--continue` 续接这个工作目录里最近用过的会话，`--session-id` 指定一个。会话服务增加列出已存会话的方法。续接时印出上一个回合的输入和回答，让用户知道接在哪里。`/sessions` 列出这个工作目录的会话，`/new` 开一个新会话。

**11. 状态行写五件事。** 模型，沙箱模式，命令的约束强度，上一次请求的输入 token 数，本会话的缓存命中率。上下文窗口的大小在调用配置里给出时，token 数后面跟上占比。状态行在输入行下面，内容取自各个服务，每次重画时现算。

**12. 符号和颜色有退路。** 输出的编码表示不了的符号换成 ASCII 的写法。环境变量 `NO_COLOR` 生效。理由：Windows 的旧控制台用的是代码页。

## 与设计文档的差异

1. 差异预览本阶段只对 `edit` 做，由调用的参数算出。`write` 显示行数和开头几行。
2. 待办面板等第 5 阶段的 `todo_write`。
3. 命令本阶段有七条。`/compact`、`/fork`、`/todos` 随各自的功能加入。
4. 会话内授权不写进日志。设计没有写明它存在哪里。
5. 忙时输入的命令不执行。设计没有写明。

## 模块与接口

### `columbina.apps.cli.terminal`（新建）

```python
@dataclass(frozen=True)
class Terminal:
    input: Input            # prompt_toolkit 的输入
    output: Output          # prompt_toolkit 的输出
    encoding: str           # 输出的编码，用来决定符号的写法

TERMINAL = ServiceKey[Terminal]("terminal")

def real() -> Terminal | None      # 标准输入输出是终端时给出它，否则 None
```

前端用 `ctx.get(TERMINAL)`，取不到就用 `real()`。两者都没有时启动失败。

### `columbina.apps.cli.lines`（新建）

```python
class Lines:
    def feed(self, text: str) -> list[str]     # 返回新落定的行
    def flush(self) -> str | None              # 把没写完的一行落定
    partial: str                               # 没写完的那一行
```

### `columbina.apps.cli.transcript`（新建）

把一个会话事件变成要印的若干段文本。它是纯函数加一点状态：哪些回复的文字已经随分片印过，每个工具调用是什么时候开始的。

| 事件 | 显示 |
|---|---|
| `user/message`，来源是 `user` 或 `steer` | 续接时印出；实时输入不重印，用户自己刚打过 |
| `user/message`，来源以 `context/` 开头 | 不显示 |
| `assistant/message` | 文字。已随分片印过的不重印。结束原因是 `max-tokens` 时加一行说明 |
| `tool/call` | 一行：工具名和对象的摘要。`edit` 另加差异预览 |
| `tool/result` | 一行：成功或错误码，用时。命令的输出给出开头几行和总行数 |
| `llm/retry` | 一行：失败的错误码和等待的时间 |
| `turn/end` | `completed` 不显示。其余的各有一行说明，带上 `detail` |
| `sandbox/mode`、`approval/policy` | 一行，写明新的取值 |

### `columbina.apps.cli.prompt`（新建）

```python
class Prompt:
    async def line(self) -> str | None          # 用户提交的一行；None 表示要退出
    async def ask(self, keys: str) -> str       # 等一个键，只认 keys 里的；Esc 给出最后一个
    def show(self, text: str) -> None           # 印到输入行上面
    partial: str                                # 画在提示里的没写完的一行
    busy: bool                                  # 决定 Esc 和提示的样子
    on_cancel: Callable[[], None]               # 忙时按 Esc 或 Ctrl+C
```

### `columbina.permissions`（修改）

```python
class Permissions:
    def standing(self, session: Session, tool: str, target: str | None) -> bool
    def grant(self, session: Session, tool: str, target: str | None) -> None
    def granted(self, session: Session) -> tuple[tuple[str, str | None], ...]
```

`standing` 说明对这一次调用能不能给"本会话都允许"。`decide` 多一个参数，表示这一次调用是否已被授权。求值顺序变成：拒绝规则，会话内授权，询问规则，允许规则，默认。

### `columbina.commands`（新建，插件，提供 `COMMANDS`）

```python
@dataclass(frozen=True)
class Command:
    run: Callable[[Agent, str], Awaitable[str]]    # 参数是命令名后面的文字，返回要显示的文字
    summary: str                                   # /help 里的一行

class Commands:
    registry: Registry[Command]
    async def run(self, agent: Agent, line: str) -> str
```

不认识的命令返回一句说明和 `/help` 的提示，不抛异常。`/help` 由这个插件自己登记。其余命令各在一个小插件里：`columbina.commands.permissions`、`columbina.commands.tools`、`columbina.commands.sessions`。`/exit`、`/new`、`/model` 由前端登记，因为它们动的是前端自己的状态。

### `columbina.session`（修改）

```python
class Sessions:
    def stored(self, cwd: str | Path) -> list[Listed]    # 这个工作目录的会话，最近用过的在前

@dataclass(frozen=True)
class Listed:
    id: str
    modified_ms: int
    first_input: str | None     # 第一条用户输入的开头
```

### `columbina.apps.cli`（新建，插件，提供 `FRONTEND`）

配置项：`model`、`cwd`、`system_prompt`、`session_id`、`resume`。`run()` 的流程是：建立或续接 Agent，登记审批的应答者，然后循环读一行，按决定 4 分派，直到用户退出。

### `columbina.apps.launcher`（修改）

没有子命令时加载 `cli` 清单。`--profile`、`--patch`、`--model`、`--cwd`、`--session-id`、`--permission`、`--allow`、`--dump-config` 两种用法共用，`--continue` 只属于交互界面。

### Task 4: 输入行

**Files:** 新建 `src/columbina/apps/cli/prompt.py`。测试 `tests/apps/cli/test_prompt.py`。

**测试要点。** 提交的一行原样给出。印到上面的内容不打断正在输入的文字。没写完的一行出现在提示里，清空后消失。忙时按 Esc 调用 `on_cancel`，空闲时不调用。空闲时 Ctrl+C 清空输入，输入为空时第二次才退出。Ctrl+D 在输入为空时退出。`ask` 期间给定的键和 Esc 按下即生效。别的键和整行的提交都不算回答，提问继续。提问结束后，原先打了一半的字回到输入行里，提问期间打的字不在。重画有节流：很快地连续更新半行，重画的次数有上限。

### Task 5: 会话内授权

**Files:** 修改 `src/columbina/permissions/__init__.py`。测试 `tests/permissions/test_grants.py`，修改 `tests/permissions/test_decide.py`。

**测试要点。** 授权之后，同一个工具对同一个对象的调用不再询问。换一个对象、换一个工具，照常询问。命中拒绝规则的调用授权了也被拒绝。命中询问规则的调用授权之后不再询问。看不懂的命令 `standing` 为假，`grant` 对它不起作用。两个会话的授权互不相干。性质测试的参照实现加上授权这一项，结论仍然一致。

## 风险

| 事项 | 处理 |
|---|---|
| 真实终端里的显示我验证不了 | 逻辑由管道测试覆盖。作者按清单手工检查，发现的问题在本阶段内修 |
| Windows 的旧控制台对转义序列和 Unicode 的支持不全 | `prompt_toolkit` 自带针对它的输出。符号有 ASCII 的退路 |
| Git Bash 的窗口不是 Windows 控制台 | 文档写明用 Windows Terminal、PowerShell 或 cmd |
| 日志或别的代码直接写标准输出，会打乱输入行 | 交互期间用 `patch_stdout` 接住，印到输入行上面 |
| 流很快时重画占用处理器 | 重画节流 |
| 审批提问期间用户正在打字 | 打了一半的字先收起来，回答之后放回 |
| 有的终端不回报光标位置，状态行不显示 | Windows 控制台和常见的终端都回报。不显示时功能不受影响 |
| 忙时提交的插话到达时回合刚好结束 | `steer` 在空闲时会开一个新回合，这是第 2 阶段已有的行为，这里有一条测试 |

## 手工检查清单

在 Windows Terminal 里，进入一个有 `AGENTS.md` 的小仓库，运行 `uv run columbina`。

1. 输入一个要读文件的问题。回复的文字应当逐段出现，不是最后一次印出。
2. 回复生成时接着打字。已输入的文字不应被冲掉。
3. 让它运行一条命令。应当出现提问，命令给出全文。按 `a`，命令运行。再让它运行同一条命令，不应再问。
4. 让它运行 `python -c "import time; time.sleep(60)"`，运行时按 Esc。几秒内回到空闲，下一个任务照常进行。
5. 回复生成时输入一句纠正并回车。模型应当在后面的回复里顾及这句话。
6. 输入 `/help`、`/tools`、`/permissions`、`/sessions`，各自有输出。
7. 把窗口拉窄再拉宽。输入行和状态行应当跟着重排。
8. 输入中文任务。显示不应有乱码。
9. 输入 `/exit`。再运行 `uv run columbina --continue`，应当印出上一个回合并接着工作。
10. 在 PowerShell 5.1 的窗口里重复第 1、3、8 项。
11. 先在 PowerShell 里执行 `[IO.File]::WriteAllText("odd.txt", "before" + [char]27 + "[2J" + "after")`，在仓库里造一个带清屏序列的文件。再让它用命令把 `odd.txt` 打印出来。屏幕不应被清空，序列的位置应当显示一个替代字符。这一项是实施中加的，见下一节"来自别处的文字"。
12. 回复生成到一半时提交一行输入。屏幕上不应留下半行回复的残影。
13. 粘贴一段多行的文字。它应当整段出现在输入行里，回车之后作为一条输入提交。这一项靠终端的"括号粘贴"，我没有办法在测试里验证。
14. 让它运行一条命令，提问出现时不要停，继续打几个字母，其中带上 `y` 或 `a`。提问不应被回答。输入行先显示三个点，停手大约半秒之后换成 `[y/n]` 或 `[y/a/n]`，这时按 `y` 才生效。这一项是复查之后加的，见记录的"首次持续集成与复查"一节。
15. 提问出现并显示选项之后，按一下 F5、Insert、Ctrl+PageUp 这类不写字的键。提问不应被回答。
16. 用 `uv run columbina --permission full-access` 启动，不给任务，先输入 `/permissions`。显示的应当是 `danger-full-access` 和 `never`，状态行也一样。

## 实施中的调整

实现时定下来而本计划没有写到的事，记在这里。阶段记录以这里为准。

**提交的顺序。** 任务 10 的三个命令插件和任务 11 的状态行排在任务 9 的前端之前提交，因为前端的模块导入它们。`/exit`、`/model`、`/new` 三条命令属于前端，随任务 9 提交。本阶段的代码先在一个单独的工作树里整体写完，再按任务逐个放进仓库，每放一个过一次闸门。中间状态暴露了一处缺口：`Permissions.set_preset` 只被命令插件的测试覆盖。权限模块因此补了自己的测试。

**任务 1。**

- 终端对象多了一个字段，说明屏幕能显示哪些符号。Windows 的旧控制台收到什么字符都照收，只显示字体里有的那些，没有办法问它。没有环境变量 `WT_SESSION` 时，符号一律用 ASCII 写法。
- `real()` 在 Windows 上还要处理一种情况：窗口自称是终端，却不是系统的控制台。这时没有终端。

**任务 3。**

- `sandbox/mode` 和 `approval/policy` 两个事件不显示。
- 工具调用的用时从审批决定之后算起，等人回答的时间不算。
- 每个回合结束后空一行。启动时的那两行和命令的回答后面也空一行。屏幕上的对话因此分成一段一段。
- 模型在没有文字到来时做的事有一个词说明：`thinking...`，或者正在准备哪个工具的调用。
- 命令的输出过长时显示末尾五行，不是开头五行。报错、汇总和退出码都在输出的末尾，只给开头的话恰好看不到它们。
- 抄本的测试逐条断言印出的行，没有用快照文件。整场对话的画面另有一份屏幕快照，见下面"测试用的终端"。

**任务 4。**

- 计划的试验认为测试里可以用 `patch_stdout`。实现时发现它和默认的输出对象在 Windows 上都要求有控制台。输入行因此自己拿输入和输出对象，不用 `patch_stdout`，日志经输入行印到上面。
- Esc 不能立刻生效。终端用 Esc 开头表示 Alt 组合键，紧跟着的键属于它。单独的 Esc 等十分之一秒才算数。
- 提问期间写字的键被吞掉，回车不算回答。计划写的是这些键落进一个空行。
- 提问的文字由 `Prompt.ask` 在轮到这个问题时印出。印出来的时候输入行已经在收答案，看到问题再按键，答的一定是这个问题。提示符换成 `[y/n]` 或 `[y/a/n]`，每个键的含义写在问题里。
- 提交一行时，没写完的半行不留在屏幕上。这是通读屏幕输出时发现的：那半行会在下一个输入行里继续增长，写完后印出，留下来就出现两次。

**任务 5。**

- `standing` 返回的不是真假，是一句话，说明一个管到会话结束的"可以"会管到哪里。`ApprovalRequest` 多了同名的字段，提问里直接用这句话。
- 授权的测试并在 `tests/permissions/test_guard.py` 里，没有另建文件。
- 权限服务多了 `set_preset` 和 `PRESETS`，给 `/permissions` 用。

**任务 9。** 一行输入首尾的空格不算，也不影响它是不是命令。此前前面带空格的 `/help` 会被当成任务发给模型。

**任务 12。**

- 启动器有了子命令 `chat`。不写子命令时就是它，命令行以选项开头时也是它。
- 把日志写到标准错误的处理器只在 `run` 时加。对话把日志印在输入行上面。
- `--cwd` 指向的不是目录时报错。此前程序照常启动，Agent 在一个不存在的目录里工作，每次工具调用各自失败。

**任务 13。** 测试里的"用户"是一个插件 `tests/support/user.py`，由清单加载。真实服务的那条测试里，它对每个提问都按同一个键，因为那里的脚本不知道模型会做什么。

**来自别处的文字。** 计划没有这一项。写测试用的终端时，要回答"一条回复能给终端发什么"，由此发现模型和工具的文字原样到了用户的终端。渲染颜色的库对夹在两个特定标记之间的内容不做处理，直接交给终端。一个被命令打印出来的文件因此可以清屏，可以改写已经显示的内容，审批提问也在其中。回复里的颜色序列会给后面的文字上色。改变文字方向的字符会让一行在屏幕上换一种顺序。

修复有两个提交。`61eed1b` 管终端里的对话，`80bb08f` 管 `columbina run` 和启动器。做法写在设计文档的 9.6 节。第一个提交之前，新写的七条测试在旧代码上全部失败。第二个提交里的每一处保护，之后的变异检查都逐个摘掉过，各有测试发现。

**测试用的终端。** 计划的做法是用纯文本的输出对象，测试读被印出和被画出的文字。屏幕上最后留下什么，这样读不出来，因为绘制输入行的库会移动光标、覆盖和擦除。这正是风险表的第一条：真实终端里的显示验证不了。

现在测试用的屏幕是一个模拟的终端，在 `tests/support/vt.py`。它执行 `prompt_toolkit` 发给 VT100 类终端的序列，留下窗口的每一行、滚出窗口的行和光标的位置。它只认识 `prompt_toolkit` 会发的序列，别的一律报错。它自己有 43 条测试，其中一条让库的输入行画在它上面，再和真实终端里应有的样子对照。

换上它之后，原有的 184 条界面测试没有一条需要改。新增 12 条测试直接断言屏幕：输入行在第一个空行，状态行在窗口最后一行，印出的内容在输入行上面而输入不丢，窗口滚动，长行由终端折行，没写完的一行原地增长，提交之后半行不留，提问占用提示符并把输入还回来，宽字符与光标位置，会操纵终端的文字不改变屏幕。端到端测试多了一份快照，是用户离开时屏幕的样子，用户输入的行也在里面。

状态行在计划的试验里被判断为"测试里看不到"。模拟终端能回答光标下面还有几行，库因此会画状态行，这一项现在有断言。

**没有做的。** 服务把一个代理对拆在两个流式事件里时，这条回复以 `MALFORMED_RESPONSE` 失败。适配器用的 JSON 解析器不接受落单的半个代理对。合并拆开的代理对留到确有服务这样做时再加。

**变异检查。** 计划写的是先加 `cli` 和 `commands` 两组。实际加了八组，共 269 个变异体。第一次运行有 24 个没有被发现，它们指向的行为各补了测试。另有一个改的是观察不到的行为，从清单里去掉了。逐组的结果见阶段记录。
