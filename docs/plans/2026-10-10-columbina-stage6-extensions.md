# Columbina 第 6 阶段实施计划：技能、钩子、子代理与 MCP

**Goal:** 不改 Columbina 的代码就能扩展它。写一份 `SKILL.md`，模型就多会一类任务。写一份 `hooks.json`，工具调用前后就多一道检查。模型可以把一件独立的事交给子代理去做。接上一个 MCP 服务器，它的工具就成了模型的工具。

**Architecture:** 四项各是一个插件，互不依赖，都只用内核已有的事件和服务。技能是一个上下文来源加一个工具。钩子桥把 `hooks.json` 里的命令挂到循环和工具管线的四个拦截点上。子代理是父 Agent 作用域之下的另一个 Agent，有自己的会话。MCP 的每个服务器由一个任务保持连接，它的工具登记进同一个工具服务，走同一条管线。为了这四项，循环和工具服务各补一处：Agent 的规格可以限定工具和步数，工具可以带着一份不是 pydantic 模型的参数说明。

**Tech Stack:** MCP 的协议层用官方 Python SDK `mcp`，作为可选的附加依赖 `columbina[mcp]`。其余三项不增加运行依赖。

设计依据是 `docs/plans/2026-10-09-columbina-design.md` 的第 7.3、11.1、11.2、11.3、11.4 节。本计划与这些章节不一致的地方列在"与设计文档的差异"一节，阶段结束时把设计文档改成一致。

## 结束标志

设计文档 15.2 给本阶段的结束标志是一句话：四项各有一个端到端示例。落到测试上是四条，每条都经 `columbina run` 的命令行和随包发布的清单运行，模型是脚本化的。

1. **技能。** 项目里有一个技能，它的正文要求按固定的格式写发布说明，并指向技能目录里的一个文件。模型的第一个请求里有技能的目录，目录里只有名称和简介。模型调用 `skill`，结果里是正文和技能目录的路径。模型再读那个文件。另一条测试把技能放在用户目录下，模型同样读得到那个文件，而用户目录下技能之外的文件读不到。
2. **钩子。** `hooks.json` 里有三个钩子。第一个在 shell 工具运行之前检查命令，命令里有约定的字样就以退出码 2 拦截，模型读到钩子给的理由，命令没有运行。第二个在 `edit` 成功之后运行，它的输出作为上下文接在结果后面。第三个在回合将要结束时检查一个文件是否存在，不存在就给出理由，模型多走一步把文件写出来，回合才结束。会话日志里每次运行各有一对 `hook/invoked` 和 `hook/result`。
3. **子代理。** 模型在一个回复里发出两个 `subagent` 调用。两个子代理各有自己的会话，同时运行，各自读文件并回答。父会话只收到两条结果，子代理读文件的过程不在父会话里。第三个调用的子代理用完了步数，父会话收到的是一条工具错误。会话列表和 `--continue` 都不把子代理的会话当成可以续接的对话。
4. **MCP。** 清单里有一个 MCP 服务器，它是测试启动的一个真实子进程，走标准输入输出。模型的第一个请求里有它的工具，名字带着 `mcp__` 前缀，系统提示里有它的说明。模型调用一个工具并得到结果。测试中途杀掉服务器，下一次调用得到一条说明连接断开的工具错误，之后服务器被重新启动，再下一次调用成功。

四项另各有一条对真实服务的测试，模型是 DeepSeek Flash，没有密钥时跳过。这四条只检查模型确实会用：给它一个与技能对得上的任务，它先调用 `skill`；让它把两件互不相干的事交出去，它在一个回复里发出两个调用。

## 范围

本阶段做的：Agent 规格里的工具限定和步数上限，回合预算插件，会话头里的委派深度，带原样参数说明的工具，标准输出与标准错误分开的进程运行。技能的发现、目录消息、`skill` 工具、读取技能文件的许可、命令 `/skills` 和 `/skill`。钩子的配置、信任、运行、五个事件的接线、命令行 `columbina hooks`。子代理的类型、接缝、进程内的提供者、`subagent` 工具、父会话里的事件。MCP 的连接保持、工具登记、结果转换、重连、命令 `/mcp`。清单、协议文档、四条端到端测试、文档。

本阶段不做的：技能正文里的参数替换和 `allowed-tools`，把技能名直接当成斜杠命令。`prompt`、`agent` 等其他类型的钩子，五个事件之外的钩子事件，钩子改写工具参数。在后台运行的子代理，可以继续对话的子代理，带着父对话分叉的子代理，子代理向用户提问。MCP 的资源、提示词、采样、征询和 OAuth。`ask_user_question` 工具。

## 约定

- 仓库根目录是 `F:\agent harness\agent-harness`。本阶段在旁边的工作树 `F:\agent harness\_review\s5` 和 `s5b` 里做，分支是 `stage-6-extensions` 和 `stage-6-b`。一个工作树跑变异检查时，下一个任务在另一个里写。闸门通过之后快进合并到本地的 `main`。不执行 `git push`。
- 提交信息用英文，末尾不加共同作者行。
- 每个任务的顺序是：写测试，看它失败，写实现，看它通过，过闸门，提交。闸门与第 5 阶段相同，运行测试时不带密钥。
- 本计划给出每个任务的文件、对外接口和要写的测试。实现代码在执行时写。接口在实现中如有调整，记在本文的"实施中的发现"一节。
- Codex 每天最多调用三次，两次之间至少隔两小时，用在大的节点上。它的每条意见先写出会失败的测试，属实才修改。
- 同一时间一个工作树里只跑一个 pytest 会话。变异检查会改动 `src`，它运行时不在同一个工作树里做别的事。
- 新增的行为各有变异体，随任务一起写进 `tests/mutation/mutants.py`。
- 一条测试如果扣住了什么不放，要在 `finally` 里放开。测试失败之后 pytest-timeout 不再计时，卡在收尾的测试会让整次运行停住。
- 参考实现的克隆在 `F:\agent harness\_reference\` 下，只读，不运行其中的代码。
- 对真实服务的调用只用于试验和四条真实接口测试。一次请求的输入超过十万 token 时先估算花费。

## 先做的试验

写计划之前做了六个试验，并请四个只读的调研任务分别读了两个参考实现里的技能、钩子、子代理和 MCP 客户端。试验的脚本和调研的摘要留在草稿目录里。调研的结论用在"设计决定"里，凡是本计划照着参考实现做的地方，实现时再对照原文核实一次。

**试验一：官方 MCP SDK 在本机的行为。** SDK 的版本是 2.3.0，安装时连带装了 29 个包。客户端是 `mcp.Client`，传入网址、`StdioServerParameters`、一个传输对象，或者同一进程里的服务器对象。试验在 Windows 上用普通的 asyncio 事件循环，对一个用同一 SDK 写的小服务器运行。

| 情形 | 结果 |
|---|---|
| 连接（标准输入输出，服务器是一个 Python 进程） | 约 1.7 秒。之后可以读到服务器的说明、名称和协议版本 |
| 列出工具 | 每个工具有名称、描述、输入的 JSON Schema、标注和输出的 Schema。标注缺省为空 |
| 调用 | 结果有内容块、结构化内容和是否出错三项 |
| 工具抛出异常，参数不合，工具不存在 | 三种都是"出错"的结果，不是异常 |
| 服务器的环境变量 | 父进程里的变量没有带过去，`DEEPSEEK_API_KEY` 也没有。`PATH` 有。配置里写明的变量有 |
| 超时设为 1 秒，工具要睡 5 秒 | 1 秒后抛出 `MCPError`，代码 -32001。服务器里的工具被取消。客户端照常可用 |
| 取消正在等待的任务 | 服务器里的工具被取消。客户端照常可用 |
| 服务器写标准错误 | 写进传给传输的文件对象。缺省是本进程的标准错误，那会把终端的输入行冲乱 |
| 同时两个调用 | 同时执行 |
| 两百万字符的结果 | 完整到达 |
| 离开客户端 | 0.06 秒。服务器进程和它启动的孙进程都结束了 |
| 调用中途服务器进程退出 | 这次调用抛出 `MCPError`"Connection closed"，代码 -32000。之后的调用同样。离开时不报错 |
| 命令不存在 | 进入客户端时抛出 `FileNotFoundError` |
| 在一个任务里进入，在另一个任务里离开 | 别的任务可以调用。离开时抛出 `RuntimeError`，因为取消作用域只能由进入它的任务退出 |

**试验二：同一进程里的服务器和 HTTP 传输。** `Client(服务器对象)` 可以直接连上同一进程里的 `MCPServer`，列出、调用、取消、超时的表现与子进程相同，所以单元测试不需要启动子进程。标注以 `ToolAnnotations` 的形式到达，其中有 `read_only_hint`。服务器运行中新增一个工具时不会自己发通知，重新列出才看得到。HTTP 传输用网址连接，调用方式相同。由进入客户端的那个任务自己发调用时，服务器一断，这次调用以 `CancelledError` 结束，离开时抛出 `ExceptionGroup`。服务器不存在时，进入客户端约两秒后抛出 `ExceptionGroup`。

**试验三：一个任务保持连接，别的任务调用。** 这是本计划要用的结构。

| 情形 | 调用方得到 | 保持连接的任务 |
|---|---|---|
| 标准输入输出，调用中途服务器退出 | 立刻得到 `MCPError`，代码 -32000 | 没有被告知，离开时不报错 |
| 标准输入输出，保持者被取消时有调用在等 | 半秒内得到 `MCPError`，代码 -32000 | 以取消结束 |
| HTTP，调用中途服务器退出 | 得到 `MCPError`，代码 -32000 | 以 `ExceptionGroup` 结束 |
| HTTP，空闲时服务器退出 | 下一次调用等了两秒，得到 `MCPError`，代码 -32000 | 没有被告知，离开时抛出 `ExceptionGroup` |
| 重新建一个客户端 | 调用成功 | |

结论有三条。客户端必须由同一个任务进入和离开，所以每个服务器要有一个专门的任务。调用方在任何一种断线情形下得到的都是同一个错误代码，没有人被挂住。保持连接的任务不一定知道连接断了，要由拿到这个错误的调用方告诉它。

**试验四：真实模型怎么用技能。** 试验用一个临时插件提供 `skill` 工具，技能的目录分三种给法：作为一条上下文消息，写在工具的描述里，不给。项目里有三个技能，其中一个要求按固定格式写发布说明，并指向技能目录里的一个文件。任务有两个，一个与这个技能对得上，一个是算一道乘法。每次都是一次真实的 `columbina run`，模型是 DeepSeek Flash。

| 目录的给法 | 任务 | 模型的调用 | 结果 |
|---|---|---|---|
| 上下文消息 | 写发布说明，三次 | 三次都先调用 `skill`，再读那个文件 | 三次格式都对。输入约 7300 个 token |
| 上下文消息 | 乘法，三次 | 没有调用 | 没有加载技能 |
| 工具的描述 | 写发布说明，一次 | 先调用 `skill`，再 `glob`，读那个文件，读 README | 格式对。输入 7441 个 token |
| 不给 | 写发布说明，一次 | 先 `glob`，在项目里找到了技能目录，再调用 `skill` | 格式对。输入 9316 个 token |

上下文消息这种给法最直接，调用最少。不给目录时，模型只找得到工作目录里的技能。三次里有两次，模型用结果里给出的绝对路径去读技能目录里的文件，所以技能在工作目录之外时，文件工具必须读得到它。样本只有一个模型、每格一到三次，结论只用来选做法，不当作统计。

**试验五：Windows 上钩子命令怎么拿到 JSON。** shell 工具在 Windows 上把命令经标准输入交给 PowerShell。钩子要用标准输入接收 JSON，命令就得换一条路进去。试验用 `-EncodedCommand` 传命令，前面加上把控制台编码设成 UTF-8 的几句，后面加上传递退出码的几句，经 `columbina.process.run` 运行。

| 情形 | 结果 |
|---|---|
| 命令启动一个 Python 程序读 JSON | 读到了，中文完好，退出码 2 传了出来。环境里要有 `PYTHONIOENCODING=utf-8` |
| PowerShell 自己读 JSON | 读到了，中文完好 |
| 一兆字节的输入没有人读 | 0.2 秒结束，没有卡住 |
| PowerShell 自己报错 | 错误流里是 CLIXML，不是文字。加 `-OutputFormat Text` 或 `-InputFormat None` 都一样 |
| 标准输出里是带中文的 JSON | 完好 |
| 九千字符的命令 | 可以运行 |
| 超时 | 被停下，没有退出码 |

另外确认了一点：`process.run` 把两个流按到达的先后合成一段文字，钩子需要把它们分开。

**试验六：真实模型什么时候委派。** 试验用一个临时插件提供 `subagent` 工具，它不真的运行子代理，只按提示词里的字样给出固定的回答。另有一条上下文消息列出一种子代理类型。四个任务各运行一次。

| 任务 | 模型的调用 |
|---|---|
| 两件互不相干的事，要求同时交给子代理 | 一个回复里两个 `subagent` 调用，都选了那种类型。之后自己用 `grep` 核对了一次 |
| 找出哪些文件导入了某个模块，没有提委派 | 自己用 `grep` 和 `glob`，没有委派 |
| 算一道乘法 | 没有调用 |
| 改 README 里的一个错字 | `read`、`edit`、`read`，没有委派 |

两条提示词都写明了项目的目录、要找什么、要报告什么，不依赖父对话。工具的描述沿用试验里的措辞。

## 设计决定

### 共同的

**1. 四项各是插件，互不依赖。** `base` 清单加入技能、钩子桥、子代理和回合预算。MCP 不进清单：有哪些服务器是用户的事，每个服务器在用户自己的清单里写一项。

**2. Agent 的规格多两项：`tools` 和 `max_steps`。** `tools` 是这个 Agent 可以用的工具名的集合，缺省是全部。工具服务是整个程序共用的一张表，所以限定落在循环里的两处：取工具声明发给模型的地方，和开始执行一次调用的地方。不在集合里的工具，模型看不到，调用了也按"没有这个工具"回答。`max_steps` 交给回合预算去执行，循环自己不看。

**3. 回合预算是一个插件。** 设计文档 7.3 说循环本体不设上限，上限由回合预算插件提供，这个插件此前没有做。它监听 `agent/pre-step`，检查三项：这个回合已经走了几步，这个回合用了多少 token，这个回合过了多少秒。任何一项到限就回答 `Reject`，回合以 `blocked` 结束，`detail` 写明是哪一项。三项的缺省值都是不限，由清单或 Agent 的规格给出。规格里的 `max_steps` 优先于清单里的。

**4. 会话头多一项 `delegation_depth`。** 普通会话是 0，子代理的会话是父会话的值加 1。列出会话和续接"上一个会话"的地方都只看深度为 0 的会话，否则 `--continue` 会接到一个刚结束的子代理上。

**5. 工具可以带一份原样的参数说明。** 工具的参数此前必须是一个 pydantic 模型，发给模型的 JSON Schema 由它导出。MCP 的工具自带 JSON Schema，把它转成 pydantic 模型再转回来会丢东西。所以 `Tool` 多一个可选的字段，给出时原样发给模型，这时参数只检查是不是一个 JSON 对象。别的检查由拿到参数的一方去做。

**6. 运行程序时可以把两个输出流分开。** `columbina.process.run` 此前把标准输出和标准错误按到达的先后合成一段文字，给 shell 工具用正合适。钩子的约定是标准输出放 JSON、标准错误放理由，所以它多一个选项，分开时两段各自有上限。

### 技能

**7. 根有五处，先找到的胜出。** 顺序是 `<项目>/.columbina/skills`、`<项目>/.agents/skills`、`<COLUMBINA_HOME>/skills`、`~/.agents/skills`、配置里的额外目录。项目根的判定与指令文件相同：从工作目录往上最近的一个含 `.git` 的目录，没有就是工作目录。同名的技能只取顺序在前的那一个，落选的记一条日志，`/skills` 里也标出来。codex 没有这条先后，同名的技能并存，模型分不清。

**8. 一个技能是一个目录，目录名就是技能名。** 路径是 `<根>/<名字>/SKILL.md`，只看一层。frontmatter 里的 `name` 必须与目录名相同，由小写字母、数字和单个的连字符组成，至多 64 个字符。`description` 必填，不能为空。两个可选的键是 `disable-model-invocation` 和 `user-invocable`，值是布尔。别的键一律忽略，这样为别的工具写的技能照样能用。但这两个键的近似拼写（驼峰或下划线）不忽略，带着它们的技能判为无效：写错一个字母就悄悄改变了谁能调用，这种错要让人看见。

**9. 读技能文件的细节。** 文件按 UTF-8 读，开头的 BOM 去掉。第一行必须是 `---`，之后要有一行 `---` 结束 frontmatter，中间用 YAML 的安全解析，结果必须是一个映射。`SKILL.md` 超过 1 MiB 的判为无效。无效的技能不影响别的技能，原因记日志，`/skills` 里列出。frontmatter 里没加引号的冒号是常见的写错，codex 会猜着修，这里不猜，报出 YAML 的原话和文件名。

**10. 项目里的技能目录不跟随链接，用户目录里的跟随。** 仓库里的东西是别人写的。项目里的技能目录如果是一个链接，它可以指向仓库之外，之后的读取许可（第 14 条）就会放模型去读那里的文件。用户自己目录里的链接是用户自己建的，常见的用法是把一个正在写的技能链到 `~/.agents/skills` 下面。这与指令文件对链接的处理是同一个理由。

**11. 目录是一条上下文消息。** 上下文来源叫 `skills`，种类是 `replace`，顺序在运行环境之后、待办清单之前。目录变了才重写，被压缩遮住之后由第 5 阶段的机制重新告诉模型。措辞用试验四里的那一段，之后每个技能一行，写名称和简介。简介里的空白压成单个空格，超过 500 个字符的截断并加省略号。只列模型可以调用的技能，按名称排序。两个参考实现里，一个把目录包在一个像系统提醒的标签里，这里不照搬，Columbina 的上下文消息有自己的框。

**12. 目录有总的上限。** 整条消息至多 12000 个字符。超出时先把各条简介按同一个长度缩短，最短缩到 80 个字符，还超就从末尾略去，并用一行写明略去了几个、用 `/skills` 可以看到全部。参考实现里一个没有上限，一个按上下文窗口的 2% 计算，这里取一个固定的数，够放一百多个技能。

**13. 每个回合开始时重新找一遍。** 上下文来源在回合开始时被问到，技能插件这时把五个根各列一遍。改了正文不会让目录重写，因为目录的文字没有变。某个根这一次读不出来时，沿用它上一次的结果，并记一条日志。一次读盘出错不应该让模型以为技能都没了。

**14. 技能目录里的文件要读得到。** 试验四里模型按结果给出的路径去读技能目录里的文件。技能在用户目录下时，这个路径在工作目录之外，文件接缝自己不放行。技能插件向接缝登记一条许可：读取这个会话的工作目录下找到的各个技能目录之内的文件。只许读，不许写。许可按接缝解析出来的真实位置判断，不按写出来的路径判断。

**15. `skill` 工具。** 参数只有 `name`。结果的开头是技能的名称、技能目录的绝对路径，和一句话：下文里不从根开始的路径都相对于这个目录。之后是正文，原样。每次调用都重新读文件，所以改了正文不用重启。调用前后各查一次这个技能是否允许模型调用，文件在两次之间被改成不允许时，这次调用失败。名字不存在时回答里列出现有的名字。frontmatter 不给模型。

**16. 人怎么调用。** `/skills` 列出技能：名称、简介、来自哪个根，以及落选的和无效的各自的原因。`/skill 名字 [任务]` 把这个技能的正文作为一条上下文交给模型，后面有任务时接着开一个回合，没有时等下一条输入。`user-invocable` 为假的技能不能这样调用。`disable-model-invocation` 为真的技能不进目录，`skill` 工具也拒绝它，只有人能调用。本阶段不把技能名直接当成斜杠命令，命令和技能各有各的名字空间，免得一个新技能盖住一条命令。

### 钩子

**17. 钩子的配置有两处，项目里的那一处要先被信任。** 用户的文件是 `<COLUMBINA_HOME>/hooks.json`，项目的文件是 `<项目>/.columbina/hooks.json`。钩子是命令，在会话开始时就可能运行。克隆一个仓库再在里面启动 Columbina，不应该等于运行这个仓库的作者写的命令。所以项目的文件只有在用户明确信任之后才生效。信任的记录是文件内容的 SHA-256，存在 `<COLUMBINA_HOME>/trusted-hooks.json` 里，由命令行 `columbina hooks trust` 写入，写之前把文件里的命令逐条印出来。文件内容一变，记录就对不上，钩子不再运行，日志里说明原因和怎样重新信任。codex 的做法更细，对每个钩子各记一个哈希，这里按文件记。

**18. 文件的格式。** 顶层是 `{"hooks": {事件名: [组, ...]}}`，每组是 `{"matcher": 匹配, "hooks": [{"type": "command", "command": 命令, "timeout": 秒}]}`。`type` 缺省是 `command`。别的类型、不认识的事件名，都略过并各记一条警告，不让整份文件作废。`timeout` 缺省 60 秒，至多 600 秒，不是正数的写法判为这个钩子无效。文件不是合法的 JSON 或顶层形状不对时，这份文件整个不用，原因记日志。

**19. 匹配。** 匹配只对两个与工具有关的事件起作用。没写、空串或 `*` 表示全部。只含字母、数字、下划线和竖线的，按竖线拆开，逐个与工具名整体比较。别的写法当作正则，要求与工具名整体匹配。正则写错时略过这一组。参考实现的正则不要求整体匹配，`Read` 会匹配上所有名字里带这四个字母的工具，这里收紧。

**20. 工具名有两套。** 为 Claude Code 写的 `hooks.json` 里用的是它的工具名。匹配时一个工具有两个名字可以对上：它在 Columbina 里的名字，和下表里对应的名字。交给钩子的 JSON 里，`tool_name` 用对应的名字，没有对应的用自己的名字。

| Columbina | 对应的名字 |
|---|---|
| `bash`、`powershell` | `Bash` |
| `read`、`write`、`edit`、`glob`、`grep` | `Read`、`Write`、`Edit`、`Glob`、`Grep` |
| `todo_write`、`skill`、`subagent` | `TodoWrite`、`Skill`、`Task` |
| `mcp__服务器__工具` | 不变 |

`tool_input` 是 Columbina 自己的参数，字段名与 Claude Code 的不全相同。作用于单个文件的三个工具另加一项 `file_path`，值是绝对路径，最常见的那类钩子（改完文件之后跑格式化）靠它就能用。

**21. 五个事件各在什么时候触发。**

| 钩子事件 | 触发的地方 | 能做什么 |
|---|---|---|
| `SessionStart` | Agent 的第一个回合开始时，作为一个上下文来源 | 输出作为上下文交给模型 |
| `UserPromptSubmit` | `agent/pre-step`，这一步认领到人写的输入时，每条输入一次 | 拦下这条输入，或者附加上下文 |
| `PreToolUse` | `tools/pre-execute` | 拒绝这次调用，或者要求先问人 |
| `PostToolUse` | `tools/post-execute`，只在工具成功之后 | 把结果换成一段理由，或者在结果后面附加上下文 |
| `Stop` | `agent/turn-stopping` | 给出理由，让模型再走一步 |

`SessionStart` 没有挂在设计文档写的 `agent/created` 上。这个事件现在不存在，而且它即使存在也只能通知，钩子的输出要等命令跑完才有，那时第一个请求可能已经发出。上下文来源在回合开始时被问到并被等待，输出一定赶得上第一个请求。`source` 是 `startup` 或 `resume`，看这个会话在此之前有没有回合。`UserPromptSubmit` 只对人写的输入触发，上下文消息和钩子自己塞进去的话不算。

**22. 命令怎么运行。** 用 shell 工具的那个 shell。Windows 上 shell 工具把命令经标准输入交给 PowerShell，钩子的标准输入要留给 JSON，所以命令改用 `-EncodedCommand` 传入，前后各加几句设置编码和传递退出码的话（试验五）。命令因此不能超过 8000 个字符。环境与 shell 工具给命令的相同，名字像密钥的变量不带过去，另加 `CLAUDE_PROJECT_DIR` 和 `COLUMBINA_PROJECT_DIR`，值都是项目根。工作目录是 Agent 的工作目录。同一个事件的几个钩子按配置里的顺序一个一个运行。回合被取消时，正在运行的钩子连同它启动的进程一起被停下。

**23. 交给钩子的 JSON。** 一行，以换行结束。每个事件都有 `session_id`、`transcript_path`、`cwd`、`hook_event_name`。`transcript_path` 是会话日志文件的路径，日志的格式是 Columbina 自己的。各事件另有：`SessionStart` 有 `source`；`UserPromptSubmit` 有 `prompt`；`PreToolUse` 有 `tool_name`、`tool_input`、`tool_use_id`；`PostToolUse` 再加 `tool_response`，是模型将要读到的那段文字；`Stop` 有 `stop_hook_active`，这个回合已经被钩子续过时为真。

**24. 怎么读钩子的结果。** 退出码 2 表示拦截，理由取标准错误，标准错误为空时用一句固定的话。两个参考实现在这一点上不一样，一个空着也拦，一个空着就不拦，这里选前一种：钩子说了拦，就不能因为它没写理由而放行。退出码 0 时看标准输出：以 `{` 开头的按 JSON 解释，别的在 `SessionStart` 和 `UserPromptSubmit` 上当作上下文，在其余事件上不用。其他退出码和超时都记为失败，不拦截。标准输出超过上限而被截断时不解释，按失败记。PowerShell 自己报的错在错误流里是 CLIXML，桥把它还原成文字。

**25. JSON 里认哪些字段。** 顶层的 `decision` 只认 `block` 和 `approve`，`block` 时理由取 `reason`。`hookSpecificOutput` 里认 `permissionDecision`（`allow`、`deny`、`ask`）和 `permissionDecisionReason`，以及 `additionalContext`，前提是其中的 `hookEventName` 与这次的事件相同。`systemMessage` 作为一条日志给人看。`continue`、`stopReason`、`updatedInput`、`suppressOutput` 不支持，出现时记一条警告。不认识的字段一律忽略。codex 的解析很严，多一个字段整段输出就作废，一个本来要拦截的钩子就这样被放了过去，这里不这样做。

**26. 几个钩子的结果怎么合并。** `PreToolUse` 取最严的一档：拒绝高于询问，询问高于允许，理由只取胜出那一档的，用空行连接。其余事件有一个拦截就算拦截。各个钩子给的上下文按顺序连接。钩子的"允许"只表示它没有异议，不能越过权限规则放行一次调用。钩子的"询问"交给审批服务，没有人可问或者会话的策略是从不询问时，按拒绝处理。

**27. 拦截各自的效果。**

| 事件 | 效果 |
|---|---|
| `PreToolUse` | 调用不执行，结果是一条错误，模型读到理由 |
| `PostToolUse` | 工具已经运行。模型读到的不是结果而是理由 |
| `UserPromptSubmit` | 回合以 `blocked` 结束。这条输入从模型看得到的对话里撤下，换成一句说明 |
| `Stop` | 理由作为一条中途的话交给模型，循环再走一步 |

撤下输入用的是第 5 阶段的顶替：一条来源为钩子的说明顶替那条用户消息，原来的事件留在日志里。不这样做的话，输入虽然被拦，下一个回合模型还是会在历史里读到它。`Stop` 在一个回合里最多续三次，再拦就记一条警告并让回合结束。两个参考实现都没有这个上限。

**28. 钩子给模型的文字有上限。** 上下文和理由各至多 10000 个字符，超出的截去中间一段并写明截去了多少。

**29. 每次运行记两条事件。** `hook/invoked` 记事件名和命令，`hook/result` 记状态、退出码、用时和理由。状态是 `completed`、`blocked`、`failed`、`timed-out` 之一。两种事件都可以略过。桥里的任何失败都只记日志和事件，不向循环抛异常。

### 子代理

**30. `subagent` 工具。** 参数是 `description`、`prompt` 和可选的 `type`。`description` 是给人看的三五个词，`prompt` 是任务。调用一直等到子代理的回合结束才返回，本阶段没有在后台运行的子代理。同一个回复里的几个调用可以同时执行。提供者里同时运行的子代理至多 4 个，多出来的排队，位置在创建子代理之前占住，创建失败时还回去。工具的描述沿用试验六的措辞。

**31. 子代理是父 Agent 之下的一个 Agent。** 它建在父 Agent 的作用域之下，父 Agent 结束时它跟着结束。它有自己的作用域，登记在父 Agent 上的监听器听不到它的事件，所以它的输出不会混进父对话的显示里。它有自己的会话，会话头里记着父会话和委派深度。它从空白的上下文开始，父对话的内容只有写进 `prompt` 的那些到得了它那里。

**32. 子代理的规格。** 工作目录与父 Agent 相同。模型、系统提示、工具和步数上限先看类型，类型没有给的取缺省：模型和系统提示与父 Agent 相同，工具是全部，步数上限是 50。无论类型怎么写，工具里都去掉 `subagent`。

**33. 子代理的权限在创建时定下。** 审批策略固定为从不询问：子代理运行时没有人在看它，需要先问人的调用一律被拒绝。沙箱模式取父会话此刻的模式。两项都在创建之后的第一次等待之前读出并写进子会话的日志。父会话里"本会话内允许"的那些许可不带给子代理，用户写在规则文件里的规则照常生效。

**34. 子代理知道自己的处境。** 另有一个上下文来源，只对委派深度大于 0 的 Agent 给出一段话：没有人可以问，遇到要问的事就写进最后的回答里，最后一条回复就是交回去的结果。

**35. 交回什么。** 回合以 `completed` 结束时，交回最后一条非空的回复。`completed` 而一个字都没有，算失败。以别的原因结束的，一律是一条工具错误，写明是怎么结束的；这之前子代理已经写出的文字附在后面，并注明它不完整。设计文档要求不把部分输出当成成功，这里把它放在错误里。结果只从子会话自己的事件里取。

**36. 取消。** 父 Agent 的这次调用被取消时，子代理以 `parent` 为由被取消。调用不管怎样结束，子代理都被关闭。

**37. 委派深度的上限是 1。** 子代理的工具里没有 `subagent`，这是第一道。工具运行时再看一次调用者的委派深度，到了上限就回答一句让它自己做，这是第二道。

**38. 类型。** 一个类型是一个 Markdown 文件，在 `<项目>/.columbina/agents/` 或 `<COLUMBINA_HOME>/agents/` 下，文件名是类型名，项目里的优先。frontmatter 有 `name` 和 `description`，可选 `tools`、`max_steps`、`model`，正文是系统提示。`tools` 里有程序里不存在的工具名时，这个类型无效，原因记日志。有哪些类型是一条上下文消息，来源叫 `agents`，没有类型时不写。类型文件和技能一样可能是别人写的，但它只能把工具收窄、换模型的名字、给一段系统提示，放宽不了权限。

**39. 父会话里记什么。** 两种可以略过的事件：`subagent/started` 记调用的 id、子会话的 id、类型和 `description`，`subagent/ended` 记结束原因和步数。终端在这两处各印一行。子代理的用量以一条 `request/aside` 记进父会话，用途写 `subagent`，这样状态行和合计里有它。

### MCP

**40. SDK 是可选的依赖。** 它连带 29 个包，其中有一整套 HTTP 服务器。不用 MCP 的人不必装。`columbina[mcp]` 装上它。没装而清单里有 MCP 的项时，插件加载失败，错误里写明要装什么。开发环境和持续集成里装着它，测试照常运行。

**41. 每个服务器是清单里的一项。** 插件是 `columbina.mcp`，配置如下。

| 键 | 含义 | 缺省 |
|---|---|---|
| `server` | 服务器在本地的名字，1 到 32 个字母、数字、下划线或连字符 | 必填 |
| `command`、`args`、`env`、`cwd` | 标准输入输出传输：要启动的程序 | |
| `url`、`headers` | HTTP 传输 | |
| `tools` | 只提供这些工具，写的是服务器给的原名 | 全部 |
| `startup_timeout_seconds` | 等它连上的时限 | 30 |
| `call_timeout_seconds` | 一次调用的时限 | 60 |
| `required` | 连不上时程序是否拒绝启动 | 否 |
| `max_instruction_bytes` | 服务器说明的长度上限 | 4096 |

`command` 和 `url` 必须有一个，不能都有。服务器进程的环境由 SDK 决定：只带 `PATH` 一类的少数变量，再加上 `env` 里写明的（试验一）。父进程里的密钥到不了它那里。

**42. 每个服务器一个保持连接的任务。** 客户端只能由进入它的那个任务离开（试验一）。所以插件为服务器起一个任务，它进入客户端、等着、最后离开。工具调用来自各自的任务，直接调用客户端的方法。

**43. 启动在后台，第一个请求之前等一等。** 插件加载时就开始连接，不挡住程序启动。每个 Agent 的第一个回合第一步之前，等所有服务器连上或者失败，至多等到启动时限。这样 `columbina run` 这种只有一个回合的运行也看得到工具。一个服务器连不上时，记一条日志，模型看不到它的工具，别的照常。`required` 的服务器在启动时限内连不上，程序不启动。

**44. 工具名。** 形式是 `mcp__<server>__<原名>`。原名里字母、数字、下划线、连字符之外的字符换成下划线。换过，或者整个名字超过 64 个字符时，取前 51 个字符，加一个下划线，再加 12 位十六进制数，它是服务器名、一个零字节和原名连起来的 SHA-256 的开头。这样一个名字只由服务器名和原名决定。插件留着从这个名字到原名的对照。一次列表里同一个原名出现两次，整份列表不用，原因记日志。

**45. 工具的描述和参数说明来自服务器，是别人写的文字。** 参数说明原样交给模型（第 5 条），根上没有 `type` 和 `properties` 的补上。描述超过 2048 个字符的截断。参数说明超过 16 KiB 的工具不提供，记一条警告：它每个请求都要发一遍。

**46. 工具的效果。** 服务器在标注里说某个工具只读（`readOnlyHint` 为真）时，它的效果算读，别的一律算运行，要过审批。标注可以说谎。对一个本机的服务器进程，这不增加风险，它本来就以用户的身份运行。对一个远程的服务器，调用本身就会把参数发出去，这一点在文档里写明。

**47. 结果怎么变成文字。**

| 内容 | 模型读到的 |
|---|---|
| 文本块 | 原文，几块之间换行 |
| 图片、音频 | 一句占位的话，写明类型和大小 |
| 资源链接 | `Resource link: 名称 (地址)` |
| 内嵌的文本资源 | 地址一行，之后是文本 |
| 内嵌的二进制资源 | 一句占位的话 |
| 没有文本块而有结构化内容 | 结构化内容的 JSON |
| 什么都没有 | 一句话，说明工具没有返回可以显示的内容 |

服务器标明出错的结果是一条工具错误，文字照上表得出。两个参考实现在结构化内容上各走一端，一个从不给模型看，一个一有就把别的内容全丢掉，这里只在没有文本时用它。结果的长度由第 5 阶段的结果上限管。

**48. 调用出问题时。** 超时回答一条错误，写明等了多久，并提醒这次调用可能已经生效。回合被取消时，取消传到服务器（试验一）。SDK 内部的取消作用域偶尔会把取消抛给调用方（试验二），这种不是本任务被取消，按错误回答。

**49. 断线和重连。** 调用拿到"连接已关闭"时告诉保持连接的任务，这次调用回答一条错误，写明连接断了、不知道它执行到了哪里，不重发。保持者离开旧的客户端，离开时抛出的任何东西都接住，然后等一会儿再连。等待从 0.5 秒起每次加倍，到 30 秒封顶，至多连 10 次。连上之后稳定满 30 秒，次数才清零，这样一个反复崩溃的服务器不会被无止境地重启。重连期间工具仍然在，这时来的调用等连接恢复，至多等到启动时限。次数用尽之后工具撤下，记一条日志。

**50. 工具列表变了。** 服务器发来列表变化的通知时，重新取一遍。取到了再换：多出来的登记，少了的撤下。取不到时保留旧的。

**51. 服务器的说明。** 作为系统提示里的一段，开头写明这是哪个 MCP 服务器对自己的说明。超过上限的截断并注明，不因此断开连接。参考实现里有一个是超长就让连接失败。

**52. 服务器写到标准错误的东西** 进文件 `<COLUMBINA_HOME>/logs/mcp-<server>.log`，不进终端。

**53. `/mcp`。** 列出每个服务器的状态（连接中、已连接、重连中、已放弃）、工具的个数和最近一次失败的原因。

## 与设计文档的差异

1. `SessionStart` 钩子不映射到 `agent/created`，而是作为一个上下文来源运行。原因见第 21 条。`agent/created` 这个事件本阶段不加。
2. 钩子的配置文件有用户和项目两处，项目的那一处要先被信任。设计文档没有写文件在哪里，也没有写信任。
3. 钩子的"允许"不能越过权限规则。设计文档写的是三档合并，没有说允许的效力。
4. 被拦下的用户输入从模型看得到的对话里撤下。设计文档只写了拦截。
5. `Stop` 钩子一个回合最多续三次。
6. 技能的根里，项目的两处不跟随链接。技能目录名必须与 `name` 相同。
7. 用户调用技能用命令 `/skill`，不是把技能名当命令。
8. 子代理类型的目录除了项目里的 `.columbina/agents/`，还有 `<COLUMBINA_HOME>/agents/`。
9. 子代理在 `completed` 而没有文字时算失败。失败时已有的文字附在错误里。
10. 子代理的用量记进父会话。
11. 会话头多一项 `delegation_depth`，会话列表和续接跳过子代理的会话。
12. MCP 的 SDK 是可选的依赖。
13. MCP 工具的效果按只读标注分成读和运行。设计文档只写了走相同的管线。
14. 重连期间到来的调用等连接恢复。重连有次数上限，用尽之后工具撤下。
15. 回合预算插件在本阶段做。设计文档把它列在守卫一类里，没有说是哪个阶段。

## 实施中的发现

1. 任务 1 和任务 3 合成一个提交，任务 14 和任务 15 合成一个提交，各自改的是同一批文件。工具的限定落在工具服务上，不在循环里：`Tools.schemas` 和 `Tools.begin` 各多一个参数 `only`，循环在这两处把规格里的 `tools` 传过去。
2. 回合预算的监听器排在 `agent/pre-step` 的最前面，别的监听器被问到之前它先回答。token 一项算的是这个回合里各次请求四种用量的合计。到限时正在进行的那一步照常走完，下一步不再开始。
3. 分叉出来的副本一律是普通对话，深度为 0，被分叉的是子代理的会话时也一样。打开着的会话后来也要知道自己的父会话和委派深度，钩子桥靠这两项判断一个会话是不是子代理的。
4. `input_schema` 必须描述一个对象，构造 `Tool` 时复制一份。两个流分开运行时，不能同时要求把完整的输出存盘，这样调用会报 `ValueError`。`Completed` 另多一个字段 `error_bytes`。
5. 计划之外抽出了六个共用的模块，都是因为有了第二个使用者：`columbina.project`（项目根在哪里，指令文件和技能共用），`columbina.frontmatter` 和 `columbina.places`（文件开头的 YAML，和进入一个根的两种方式，技能和子代理类型共用），`columbina.shells`（用哪个 shell、命令得到什么环境，shell 工具和钩子共用），`columbina.plain_yaml`（读别人写的 YAML），`columbina.text`（把文字补整）。钩子的两处文件另由 `columbina.hooks.files` 统一去找和读。
6. PyYAML 的安全解析会抛出不是 `YAMLError` 的错误：不存在的日期和超过 4300 位的数字是 `ValueError`，`!!bool maybe` 是 `KeyError`，嵌套太深是 `RecursionError`。几行 YAML 还能造出互相包含的列表，对它取 `repr` 没有尽头，所以报错时不显示容器的内容，标量只显示前 60 个字符。复查之后又加了两条：别名一律拒绝，因为合并键能把三十行展开成约十亿个条目；写不出来的大整数判为读不出来的值。技能、子代理类型和项目的权限规则都经 `columbina.plain_yaml` 读。（第 9 条）
7. `Path.resolve(strict=True)` 在 Python 3.13 之前对成环的链接抛出 `RuntimeError`，在 Windows 上用两个目录联接见到过。跟随链接改用 `os.path.realpath(strict=True)`。项目里的根还多一道检查：打开任何东西之前，先逐级查看路径上有没有链接。系统是先打开链接指向的地方，之后才说得出它在哪里，链接指向另一台机器时，打开这一下已经把连接发了出去。（第 10 条）
8. 两个可选键的近似拼写只按字母认：不分大小写，去掉连字符和下划线，`invok` 当作 `invoc`。根里读不出来的一项记为无效，不让整个根作废。读取许可按文字比较目录，不按 `Path` 对象比较，后者在 Windows 上不分大小写。（第 8、14 条）
9. 技能不只在回合开始时找一遍。有人问就找：回合开始时，模型调用 `skill` 时，人要列表时。技能全都没了的时候，目录消息换成一句说明。（第 13 条）
10. 第 7 条的第四个根 `~/.agents/skills`，随包发布的清单没有配置。插件的配置里有这一项（`user`），但清单里没有表示用户主目录的变量，所以默认的程序不找这一处，要用的人在自己的清单里写。
11. 信任的记录按文件的位置和内容的 SHA-256 两样记，不只记内容：同样的内容放在另一个目录里是另一批命令。命令行多了 `columbina hooks distrust`，信任给得出去就要收得回来。`trust` 先把命令显示出来，确认输出已经送出，再写记录。不含任何钩子的项目文件不需要信任。钩子文件最多读 256 KiB。配置里的两个文件必须写绝对路径。（第 17 条）
12. `PreToolUse` 没有挂在 `tools/pre-execute` 上，而是工具服务的一个守卫。挂在事件上时，钩子要求先问人是经插件自己的上下文去问的，一个会话的回答者能放行另一个会话的调用。守卫拿到的是这次调用的上下文，而且只能拒绝，"钩子的允许越不过权限规则"由结构保证。（第 21、26 条）
13. `UserPromptSubmit` 不只看这一步认领的输入。每一步开始之前，钩子被问到的是上一次 `step/start` 之后、模型还看得到、此前没有放行过的每一条人写的输入。否则被别的监听器拦下的步、第一步之前就失败的回合，都会把没有检查过的输入留给下一个回合的模型。（第 21 条）
14. 同一时刻的几个钩子各自接住自己的失败，一个出错不影响别的钩子已经给出的回答。合并之后的文字连同截断的说明一起受第 28 条的上限。命令的长度按 UTF-16 的单元计，Windows 是按这个单位接收命令行的。（第 22、26、28 条）
15. `SessionStart`、`UserPromptSubmit` 和 `Stop` 不对子代理的会话运行：没有人的会话随它开始，它的任务是 Agent 写的，为对话的回合写的钩子不该决定它的回合能不能结束。两个与工具有关的事件对子代理照常运行。
16. Python 的字符串里可以有半个字符（单独的代理项）。会话日志按 UTF-8 写，写不进去，回合就以错误结束。它有四个入口：钩子的回答，工具的结果（文件名里可以有），人的输入，上下文来源。四处都在进来的地方经 `columbina.text.whole` 补整。交给钩子的 JSON 里，这种字符按 JSON 的写法转义，不丢掉。模型的回复带不进来：适配器读每个事件用的 JSON 解析会拒绝它，请求以 `MALFORMED_RESPONSE` 失败。
17. 子代理的类型文件里，不认识的键让这个类型无效，写错的键会指出本来想写的是哪一个。技能对未知的键是忽略，类型不能这样：把 `tools` 写成 `tool`，一个本该只有一个工具的子代理就拿到了全部工具。类型文件至多 64 KiB，以点开头的文件略过。`tools` 里有不存在的工具名的类型按根去掉，在合并各个根之前做，所以它不会盖住另一处的同名类型。（第 38 条）
18. 类型只能收窄。步数取配置和类型里较小的那个。工具不会多于父 Agent 的。项目里的类型不能换模型，写了也仍然用父 Agent 的模型，并记一条警告：模型花的是用户的钱，项目是别人写的。用户目录里的类型可以换，换了之后不沿用父模型的窗口。（第 32、38 条）
19. `subagent` 工具的一次调用缺省有半小时的时限。Agent 原先知道的类型都没了的时候，模型会被告知。`subagent/started` 写在负责关闭子代理的那层保护之内。等子代理停下时顶住后续的取消，至多 10 秒，这样它的用量总能记进父会话。（第 30、36、39 条）
20. MCP 的测试目录是 `tests/mcp_client`，不是 `tests/mcp`。`tests` 在测试的导入路径上，一个叫 `mcp` 的目录会被当成 SDK。
21. 服务器的名字比第 41 条收得紧：字母、数字和连字符，中间可以有单个的下划线，至多 32 个字符。两个连着的下划线只用来分开服务器名和工具名，所以两个服务器得不到同一个完整的名字。参数说明的根不是对象的工具不提供。（第 41、44、45 条）
22. 保持连接的是一个保持者加每次尝试一个任务，不是一个任务管到底。离开客户端至多给 10 秒，被迫中断的任务不再用于下一次尝试。（第 42、49 条）
23. SDK 2.3.0 对同一 SDK 写的服务器缺省用 2026-07-28 版的协议，工具列表的变化只经订阅到达。2025-11-25 版才是一条通知。连接两种都处理，服务器的配置多了一项 `protocol`，取 `auto` 或 `legacy`。订阅着的连接不等调用就能发现断线，试验三的结论（只有调用方知道）只对不订阅的连接成立。（第 49、50 条）
24. 先订阅，再列工具。原来的顺序相反，两者之间发生的变化没有人收到，工具表在这次连接里就一直是旧的。本机的 Python 3.11 碰巧不在两者之间调度测试，持续集成的 Python 3.12 会：五条测试在三个系统上都失败，其中四条指向这个问题，第五条是测试自己看得太早。（第 50 条）
25. 回合等服务器的地方比第 43 条多：拼系统提示之前等一次，每一步之前也等。等的是每个服务器的第一次尝试结束，所以 `MCP.ready()` 不带时限参数，第一次之后不再花时间。服务器列表的插件多了配置 `log_dir`。
26. 调用的时限管整次调用，把请求写给服务器也算在内，不再交给 SDK。SDK 的时限从请求写出之后才开始算，服务器不再读输入时永远到不了。连接保持了多久算到断开的那一刻，离开连接花的时间不算，否则一个每 25 秒崩溃一次、退出又很慢的服务器会被当成稳定的。（第 48、49 条）
27. 断线只告诉用户一次，一行。此前用户读到什么取决于谁先发现：订阅先断时读到一句关于工具列表的话，调用先发现时什么都读不到。这是第一次用真实的服务器进程运行时发现的。（第 49 条）
28. 结束标志的第 4 条里，服务器不是被测试从外面杀掉的，而是在一次调用里结束自己的进程。说 2026 版协议的服务器多半在下一次调用到来之前就被发现断线，那次调用会等新的进程并成功，模型读不读得到错误成了竞争。
29. 协议文档没有等到任务 19。`tests/protocol` 的测试要求新增的事件同时出现在事件表、Schema 和样例会话里，所以会话头的新字段随任务 3 提交，两种钩子事件随任务 11，两种子代理事件随任务 14 和 15。附加依赖 `mcp` 和锁文件随任务 16。
30. 终端上钩子的显示比计划多。钩子运行期间，回复将要出现的那一行写着是哪个钩子。`Stop` 钩子让回合继续时，印出它给的理由的开头。被拦下的调用和输入，在各自生效的地方本来就有显示。
31. 脚本化模型的 `when` 不能是空串。脚本里只剩给别的请求的回复时，对这个请求来说脚本就到头了。
32. 新的变异体组比计划多四个：`trust`（命令行 `columbina hooks`）、`yaml`、`scripted` 和 `extensions`。
33. 任务 21 里四项的说明写进使用指南（`docs/guide.md` 和它的中文、日文版），README 只加一句。README 在本阶段中途按作者的要求改短了，只讲下载和部署。指南里的四个例子各有一条测试，把例子原样取出来交给读它的代码。
34. 结束标志的第 4 条之外补了一条端到端测试：没有规则、也没有人可问时，服务器的工具不被调用。写它的时候发现，这类调用需要同意的理由是为命令写的，用户另有放行的规则时甚至说没有规则能放行它。运行某种东西而不给出命令的工具，现在有自己的一句话，判定不变。这类工具没有本会话内的同意，每次调用都要问，除非有一条写明工具名的规则。（第 46 条）

## 模块与接口

### `columbina.agent` 与 `columbina.agent_loop`（修改）

`AgentSpec` 多两个字段：`tools: frozenset[str] | None = None`，`max_steps: int | None = None`（至少为 1）。循环在取工具声明时只取 `tools` 里的，在开始一次调用时拒绝 `tools` 之外的名字，回答与工具不存在时相同，列出的现有工具也只有允许的那些。

### `columbina.guard.budget`（新建，插件 `turn-budget`）

配置 `max_steps`、`max_tokens`、`max_seconds`，都可以不给。监听 `agent/pre-step`。步数取 `StepInfo.step`，token 取会话用量在这个回合里的增量，时间取回合第一步被问到时起算。到限时回答 `Reject`，理由是一句话，例如 `the turn has taken its 50 steps`。Agent 规格里的 `max_steps` 优先于配置里的。

### `columbina.session`（修改）

`SessionHeader` 多一个字段 `delegation_depth: int = 0`。`Sessions.create` 和 `Agents.create` 多两个只能按名字给的参数 `parent` 和 `delegation_depth`。`Sessions.stored` 返回的每一项带着深度，`columbina sessions list`、`/sessions`、`--continue` 和 `sessions show` 的列表只取深度为 0 的。`sessions show ID` 可以看任何一个会话，子代理的会话在开头写明它是哪个会话委派的。

### `columbina.tools`（修改）

`Tool` 多一个可选字段 `input_schema`。给出时 `schema` 用它，`parameters` 必须是新导出的 `JsonArguments`（一个根模型，值是任意的 JSON 对象），`parse` 只检查参数是不是 JSON 对象。两者不配套时构造 `Tool` 就报错。

### `columbina.process`（修改）

`run` 多一个参数 `streams: Literal["joined", "apart"] = "joined"`。`apart` 时 `Completed.output` 只有标准输出，新字段 `error_output` 是标准错误，两段各自按 `max_output_bytes` 保留头尾，`omitted_bytes` 之外另有 `error_omitted_bytes`。`joined` 时行为不变，`error_output` 为空。

### `columbina.llm.adapters.scripted`（修改）

配置里的一条回复可以带 `when`，值是一段文字。请求的最后一条用户消息里有这段文字时才用这条回复，同样带 `when` 的回复按配置里的顺序各用一次。不带 `when` 的回复照旧按顺序用。两个子代理同时运行时，请求到达的先后不固定，端到端测试靠它把回复对到正确的 Agent 上。

### `columbina.skills`（新建，插件 `skills`）

`files.py` 是纯函数：`parse(text) -> Skill | Invalid`，`discover(roots) -> Found`。`Skill` 有 `name`、`description`、`directory`、`root`、`model_invocable`、`user_invocable`。`Found` 有 `skills`（按名字，胜出的）、`shadowed`、`invalid`。

`__init__.py` 提供服务 `SKILLS`：`found(cwd) -> Found`，`body(skill) -> str`。配置 `home`（缺省 `${COLUMBINA_HOME}/skills`）、`extra`（目录的列表）、`catalog_max_chars`（12000）。它登记上下文来源 `skills`、工具 `skill` 和文件接缝的一条许可。许可需要文件接缝，接缝不在时技能照常工作，只是工作目录之外的技能文件读不到。

### `columbina.commands.skills`（新建，插件 `command-skills`）

`/skills` 和 `/skill 名字 [任务]`。

### `columbina.hooks`（新建，插件 `hooks`）

`config.py`：`read(path) -> Hooks`，`matches(group, names) -> bool`，`trusted(path, record) -> bool`，`trust(path, record)`。`Hooks` 按事件给出组的列表，另有读取时的警告。

`run.py`：`invocation(command) -> (argv, 环境)`，按平台不同；`payload(event, ...) -> bytes`；`read_result(event, completed) -> Result`；`merged(results) -> Result`；`from_clixml(text) -> str`。`Result` 有 `status`、`decision`（`allow`、`ask`、`block` 或没有）、`reason`、`context`、`message`。

`__init__.py`：配置 `user_file`（缺省 `${COLUMBINA_HOME}/hooks.json`）、`trust_file`（缺省 `${COLUMBINA_HOME}/trusted-hooks.json`）、`project`（是否读项目的文件，缺省是）、`max_stop_continuations`（3）、`max_context_chars`（10000）。它监听 `agent/pre-step`、`tools/pre-execute`、`tools/post-execute`、`agent/turn-stopping`，登记上下文来源 `hooks`（种类 `note`），声明事件 `hook/invoked` 和 `hook/result`。配置文件在每个回合开始时重读一次，改了不用重启。

### `columbina.apps.hooks`（新建）与启动器（修改）

`columbina hooks list` 印出两处文件里的钩子和项目文件是否被信任。`columbina hooks trust` 印出项目文件里的命令并记下它的哈希。两个子命令都接受 `--cwd`。这两个子命令不加载模型和 Agent。

### `columbina.subagents`（新建，接缝，插件 `subagents`）

服务 `SUBAGENTS`：`providers` 是提供者的注册表；`run(parent, Task) -> str` 用配置里指名的提供者运行一个子代理并交回结果，失败时抛出 `SubagentFailed`，其中有结束原因和已有的文字。`Task` 有 `call_id`、`description`、`prompt`、`type`。`types.py`：`parse`、`discover(cwd, home, tools) -> Types`，形状与技能的相同。事件 `subagent/started`、`subagent/ended`。配置 `provider`（`spawn`）、`max_running`（4）、`max_depth`（1）、`max_steps`（50）、`home`（缺省 `${COLUMBINA_HOME}/agents`）。

### `columbina.subagents.spawn`（新建，插件 `subagent-spawn`）

进程内的提供者。它在父 Agent 的作用域下创建子 Agent，定下权限，交给它任务，等它的回合结束，取结果，关闭它。

### `columbina.builtin_tools.subagent`（新建，插件 `tool-subagent`）

工具 `subagent`，上下文来源 `agents`（类型的目录）和 `delegated`（子代理的处境）。

### `columbina.mcp`（新建，插件 `mcp`）与 `columbina.mcp.server`（新建，插件 `mcp-server`）

`columbina.mcp` 提供服务 `MCP`：`servers` 是已登记的服务器的表，`ready(seconds)` 等所有服务器连上或失败。它监听 `agent/pre-step`，在每个 Agent 的第一个回合第一步之前等一次。这个插件不导入 SDK，在 `base` 清单里。

`columbina.mcp.server` 是每个服务器加载一次的插件，配置见第 41 条。它导入 SDK，起保持连接的任务，登记工具和系统提示的一段，把自己登记到 `MCP`。纯函数分在三个文件里：`names.py`（`tool_name(server, raw)`），`schema.py`（`repaired(schema)`、大小检查），`content.py`（`shown(result) -> str`）。`connection.py` 是保持连接的 `Connection`：`start()`、`call(raw_name, arguments, seconds)`、`state`、`tools`、`instructions`，以及工具列表变化时的回调。

### `columbina.commands.mcp`（新建，插件 `command-mcp`）

`/mcp`。

### 终端界面、清单与协议文档（修改）

终端在 `subagent/started` 和 `subagent/ended` 处各印一行，在钩子拦截时印一行。`base.yml` 加入 `turn-budget`、`skills`、`hooks`、`subagents`、`subagent-spawn`、`tool-subagent`、`mcp`。`cli.yml` 加入 `command-skills`、`command-mcp`。`pyproject.toml` 加入附加依赖 `mcp`，开发依赖里也加。协议文档的事件表加入四种新事件，`events.schema.json` 和样例会话重新生成，样例会话里新增的每种事件至少出现一次。
