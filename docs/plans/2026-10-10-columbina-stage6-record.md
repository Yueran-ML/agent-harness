**2. 钩子。** 用户的 `hooks.json` 里有三个钩子，命令是测试写的 Python 脚本。第一个匹配 `Bash`，命令里有约定的字样就以退出码 2 拦截。那条命令有一条规则允许，仍然没有运行，模型读到钩子写在标准错误里的理由，错误码是 `HOOK_BLOCKED`。第二个匹配 `Edit`，在 `edit` 成功之后给出一段上下文，它接在结果后面。第三个是 `Stop` 钩子：回合将要结束时 `CHANGES.md` 还不存在，它以退出码 2 给出理由，模型读到这个理由，多走一步把文件写出来，回合以 `completed` 结束。会话日志里有四对 `hook/invoked` 和 `hook/result`，状态依次是 `blocked`、`completed`、`blocked`、`completed`。项目里的 `hooks.json` 要先被信任才运行，这一条由 `tests/apps/test_hooks_command.py` 检查：用命令行信任一个文件，再让会话运行它的钩子。

## 做出来的东西

**地基。** Agent 的规格多了两项：`tools` 限定这个 Agent 可以用哪些工具，`max_steps` 是一个回合的步数上限。插件 `turn-budget`（`columbina.guard.budget`）在每一步开始之前检查步数、token 和时间三项，到限时回合以 `blocked` 结束。会话头多了 `delegation_depth`，列出会话和续接的地方只看深度为 0 的。工具可以带一份原样的 JSON Schema。`columbina.process.run` 可以把标准输出和标准错误分开。

**技能。** `columbina.skills.files` 读 `SKILL.md`，在各个根里找技能，不知道 Agent 和工具。插件 `skills` 把技能的目录作为一条上下文消息交给模型，每个技能一行。它提供工具 `skill`，结果是技能目录的路径和正文。它还向文件接缝登记一条许可，让工作目录之外的技能目录里的文件读得到，只许读。命令 `/skills` 列出技能，以及落选的和无效的各自的原因。`/skill 名字 [任务]` 由人把一个技能交给模型。

**钩子。** `columbina.hooks.config` 读 `hooks.json`，做匹配，管信任的记录。`columbina.hooks.run` 运行一个钩子的命令：把发生的事作为一行 JSON 写进它的标准输入，按退出码和标准输出读它的回答，再把同一时刻几个钩子的回答合并。插件 `hooks` 是桥，在五个时刻运行钩子，并照回答去做。每次运行在会话日志里留一对 `hook/invoked` 和 `hook/result`。命令行 `columbina hooks` 有三个子命令，不加载模型和 Agent。

**子代理。** `columbina.subagents.types` 读类型文件。插件 `subagents` 是接缝，它决定谁可以委派、子代理的规格怎么定、同时运行几个、交回什么、父会话里记什么。插件 `subagent-spawn` 是进程内的提供者：子代理是父 Agent 作用域之下的另一个 Agent，有自己的会话，审批策略固定为从不询问，沙箱模式取父会话当时的。插件 `tool-subagent` 提供工具 `subagent` 和两个上下文来源：类型的目录，和告诉子代理它的处境的那一段。父会话里记 `subagent/started` 和 `subagent/ended`，子代理的用量以一条 `request/aside` 记进父会话。终端在子代理开始和结束时各印一行。

**MCP。** 插件 `mcp`（`columbina.mcp`）提供服务器的列表，不导入 SDK。插件 `mcp-server`（`columbina.mcp.server`）每个服务器加载一次。`names.py`、`schema.py` 和 `content.py` 是纯函数：工具的名字，参数说明的修补和大小检查，结果怎样变成文字。`connection.py` 保持连接：连上，列出工具，调用，断线后按退避重连，工具列表变了就换表。`reach.py` 是两种传输，`offer.py` 把服务器的工具变成工具服务里的工具，`served.py` 是程序其余部分看到的一个服务器。命令 `/mcp` 列出每个服务器的状态、工具的个数和最近一次失败的原因。SDK 是可选的附加依赖 `columbina[mcp]`。

**清单、界面与协议文档。** `base` 清单加载 `turn-budget`、`skills`、`hooks`、`subagents`、`subagent-spawn`、`tool-subagent` 和 `mcp`，`cli` 清单多了 `command-skills` 和 `command-mcp`。模型因此多了两个工具，终端多了三条命令。钩子运行期间，终端上写着是哪个钩子。协议文档的事件表、Schema 和样例会话加入了四种新事件和会话头的新字段。

**脚本化的模型。** 配置里的一条回复可以带 `when`，只回答最后一条用户消息里有这段文字的请求。两个子代理同时发请求时，测试靠它把回复对到正确的 Agent 上。

15. 服务器的工具需要同意时，理由用它自己的一句话说，不借用为命令写的话。

## 实施中找到的问题

**持续集成找到的。** 任务 17 的连接测试第一次在 Python 3.12 上运行时，有五条在三个系统上都失败，本机的 3.11 上全部通过。其中四条指向同一个问题：连接先向服务器要工具列表，之后才订阅列表的变化，两者之间发生的变化没有人收到。3.11 的调度顺序碰巧不让测试落在两者之间，3.12 会。修复是先订阅再列，在 `6ecbc63`。第五条是测试自己看得太早。新补的一条测试让工具在第一次列出的途中变化，它在修复之前的代码上，在每个版本的 Python 上都失败。

## 已知的限制

1. **连接的三条复查意见没有关闭。** 第 7 条：程序只在自己的日志器上装了处理器。SDK 和 HTTP 库写的日志到根日志器，那里没有处理器，Python 把警告以上的记录直接写到标准错误，也就是终端，或者桌面应用的日志文件。HTTP 库在 INFO 一级记下完整的地址，这一级缺省不输出。地址的路径里如果有密钥，没有任何一处知道它是密钥。第 9 条：关闭在时限内没有完成时，`close()` 照样返回，保持连接的任务和传输可能还活着，之后没有办法再等它们收尾。第 13 条：订阅断了之后只重新列一次工具，不再订阅，这次连接里此后的变化收不到。
2. **`~/.agents/skills` 默认不找。** 插件的配置里有这一项，随包发布的清单没有配置它。清单里没有表示用户主目录的变量，原先打算由启动器给出一个，没有做。别的工具放在那里的技能要不要默认读进来，留给作者定：它会改变每个会话里模型被告知的内容。
3. **MCP 的 HTTP 传输没有对真实服务器的测试。** 测试里 HTTP 客户端和 SDK 的传输函数都是替身。真实的 HTTP 服务器只在写计划之前的试验二和试验三里运行过。端到端测试和真实接口测试用的都是标准输入输出。
4. **MCP 只接工具。** 资源、提示词、采样、征询和 OAuth 都没有做。服务器的只读标注可以说谎。对远程的服务器，调用本身就把参数发了出去。
5. **钩子只有命令一种类型和五个事件。** `continue`、`stopReason`、`updatedInput` 和 `suppressOutput` 不支持，出现时记一条警告。`tool_input` 是 Columbina 自己的参数，字段名与 Claude Code 的不全相同。
6. **子代理只在前台运行，只委派一层。** 它运行期间没有人可问，需要先问人的调用一律被拒绝。程序在子代理工作时退出，父会话的日志里就只有 `subagent/started`。
7. **回合预算到限时没有单独的代码。** 回合以 `blocked` 结束，`detail` 是一句英文，界面无法按代码把它和别的拦截分开。
8. **服务器的工具没有"本会话内不再询问"这一档。** 每次调用都要问，除非有一条写明工具名的规则。命令可以按原样的一行记住一次同意，这类工具没有这样一个可以记住的对象。要不要按工具记住，留给作者定。
9. **模型的回复里有被切成两半的字符时，请求会失败。** 适配器读每个事件用的 JSON 解析拒绝半个字符。服务把一个字符的两半切在两个事件里时，请求以 `MALFORMED_RESPONSE` 结束。
