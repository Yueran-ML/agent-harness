# Columbina 视频剪辑设计（草案）

**状态:** 草案，等作者确认。确认之前不写实施计划，也不写代码。文中标着“待试验”的地方，结论要等写计划之前的试验做完才算数。

**Goal:** 让 Agent 能剪视频。第一版做两件事：按文字剪口播，和一条能放画面、配乐、标题的多轨时间线。转写在本机做，成片用系统里的 ffmpeg 导出。这一阶段只做内核和命令行，界面放到之后。

**来源:** 作者读了两份关于别的剪辑程序怎样让模型改时间线的技术分析，材料不在仓库里。这里只取做法，每一处都按本仓库已有的部件重新设计。没有取任何文字，交给模型的话到时候自己写。

主设计文档是 `docs/plans/2026-10-09-columbina-design.md`。视频剪辑是后来加的方向，那里还没有它。本文确认之后在那里补一节。

## 1. 范围

第一版做的：

1. 导入素材，查清每个文件的时长、画幅、帧率和音轨。
2. 在本机把口播转写成带逐词时间的文字。
3. 按文字剪：删掉口头语、重复和说错重来的句子，缩短停顿，调整句子的先后。
4. 多轨：在口播上面盖画面，下面垫音乐，加标题和字幕，片段可以裁切、缩放、摆位置、变速，片段之间可以叠化。
5. 导出成片和字幕文件，另有一档又快又小的预览。
6. 每一次修改都能撤销。

第一版不做的：生成画面、配音和数字人。云端转写，但留好接缝。带播放器的界面。多机位对齐、调色、关键帧动画、特效插件。多人协作。

**结束标志。** 给一段几分钟的真实口播录像、几段画面素材和一首音乐，用一句话提要求，Agent 在无界面模式下交出成片：口头语和重来的句子剪掉了，长停顿缩短了，指定的几句话上面盖着画面，音乐在人声底下自动压低，带字幕，另有一份 `.srt`。同一流程有脚本化模型的测试，用生成出来的纯色画面和单音来核对剪点。

## 2. 需要作者决定的事

下面八件事决定了这一块长什么样。每件都给了建议，正文按建议写。

| 事情 | 建议 | 另一种做法和取舍 |
|---|---|---|
| 模型在哪里改口播 | 改一个文本文件。稿子就是工作目录里的 `story.md`，用已有的 `read`、`edit`、`grep` 来读和改，再用一个工具核对并提交 | 一组专门的结构化操作，每次调用带上“哪一句、哪几个词”。不用解析文本，但人不能直接改，也用不上现成的文件工具 |
| 时间线的形状 | 一条主线加挂在主线上的片段。主线是口播，前后相接不留缝。画面、音乐、标题挂在主线的某句话上，那句话挪动，它们跟着走 | 自由的多轨，每个片段各记各的时间。更通用，但主线一改，上面的东西全部错位 |
| 用什么处理媒体 | 系统里装好的 ffmpeg 和 ffprobe，不随包分发。渲染就是把时间线编译成 ffmpeg 的参数 | 用 Python 的媒体库在进程内处理。多一批很重的依赖，换来的控制力这一版用不上 |
| 用什么转写 | 接缝加一个本机的提供者 faster-whisper，作为可选依赖。模型文件由用户明确下载，程序不悄悄下载 | whisper.cpp 的命令行程序。Python 依赖为零，但要用户另装一个程序。可以以后作为第二个提供者 |
| 工程存在哪里 | 工作目录下的一个目录，里面是 JSON 文件和稿子。素材只记路径，不复制 | 一个数据库文件。查询方便，但看不了差异，也没法手改 |
| 时间用什么单位 | 时间线上用整数帧，帧率是一个分数。素材里的位置用整数微秒 | 全部用秒的小数。简单，但 29.97 帧这类帧率上会累积误差 |
| ffmpeg 在哪里运行 | 在本机，和文件工具一样，不进容器。它读写的每个路径都过文件接缝 | 进容器。素材常常在工作目录之外，体积又大，挂载和性能都不合适 |
| 这一阶段有没有界面 | 没有。有给人用的命令 `columbina video …`，和模型用的是同一套函数 | 先做界面。作者已经定了先内核 |

还有三件事要作者帮忙：

- 一段用来验收的真实素材：几分钟的口播，几段画面，一首音乐。没有的话，我用系统自带的语音合成做一段。
- 同意在本机装 faster-whisper 和它要的 GPU 运行库，并下载一个 Whisper 模型。本机是 RTX 4080，12 GB 显存，够用最大的模型。
- 这一块在阶段表里怎么排。建议不改现有的编号，单独叫“视频一”到“视频五”，排在补强计划的第二组之后。

## 3. 架构

```
素材文件 ──导入──▶ 工程目录
                    ├─ project.json      清单：画幅、帧率、素材表
                    ├─ transcripts/      每个素材的逐词转写
                    ├─ timeline.json     时间线：主线留了哪些词，挂了哪些片段
                    ├─ story.md          稿子：主线的文本，给人和模型改
                    ├─ history/          每次提交之前的时间线
                    ├─ cache/            抽出的音频、静音检测的结果，删了可以重建
                    └─ out/              预览、成片、字幕

story.md ──提交──▶ timeline.json ──编译──▶ ffmpeg 的参数 ──运行──▶ out/
```

代码是一个插件包 `columbina/video/`，由一份组合清单带上，不带的时候 Agent 没有这些工具，也不要求机器上有 ffmpeg。包里分六块：

| 模块 | 管什么 | 碰不碰系统 |
|---|---|---|
| `media` | 找到可信的 ffmpeg，问版本，查文件，抽音频，找静音，抽一帧，运行渲染 | 碰，经 `process.run` |
| `transcribe` | 转写的接缝，一个假的提供者，一个本机的提供者 | 提供者在另一个进程里 |
| `project` | 工程的数据模型，读写和撤销 | 只碰工程目录 |
| `story` | 时间线到稿子，稿子到“留哪些词”，词到片段 | 不碰，纯函数 |
| `render` | 时间线到 ffmpeg 的参数，时间线到字幕文件 | 不碰，纯函数 |
| `tools` | 给模型的工具，给人的命令 | 调上面几块 |

纯函数的三块是这一阶段大部分的逻辑，测试不需要 ffmpeg，可以用属性测试和变异体压实。

**用到的现有部件。** 路径都经文件接缝定位和判断：写工程目录要 `workspace-write`，读工作目录之外的素材按现有规则询问。ffmpeg 经 `process.run` 运行，超时、取消和进程树的收尾是现成的。稿子是普通文件，模型读过才能改，提交之后稿子重新生成，旧的读取自动作废，这正是文件接缝已有的规矩。稿子被压缩拿走之后可以重读。转写和渲染的长输出走已有的存盘。

## 4. 数据模型

**素材（asset）。** 一个源文件。记路径、种类、时长、画面的宽高帧率和旋转、音频的采样率和声道，另记一份身份：大小、修改时间，和文件头尾各一小段的摘要。文件被换掉时身份对不上，程序会说，不会拿旧的转写去剪新的文件。

**转写（transcript）。** 属于一个素材。一串词，每个词有编号、起止时间（微秒）、文字和置信度。词按停顿和标点分成句，句是稿子里的一行。中文没有空格，一个“词”可能是一两个字，显示时不加空格。改错别字是另一层：只改显示的文字，不动时间。

**时间线（timeline）。** 三部分。

- 主线：一串句子的引用，各带一张“这句里留哪些词”的表，和各处停顿留多长。主线不直接存片段的起止帧，片段每次由词算出来，所以稿子和时间线不会各说各话。
- 挂件：盖在主线上的画面、垫在下面的声音、标题。每个挂件记它挂在哪个素材的哪一刻，那一刻在主线上的位置就是它的位置。那一刻被剪掉时，挂件变成“没处挂”，留在工程里，提交的回执里指出来。也可以不挂，直接写第几帧，比如从头铺到尾的音乐。
- 转场：记在主线相邻两段之间，叠化多少帧。

挂件的属性：裁切、缩放方式、位置、不透明度、音量、淡入淡出、恒定的变速。字幕不是挂件，它由主线留下的词自动生成，只有开关和样式。

**从词到片段。** 这是按文字剪的核心，是一个纯函数。连着留下的词合成一段。段的两端落在词与词的空隙里，默认留一小段余量，优先落在检测到的静音上，最后对齐到帧。空隙太短、落点在连着说的两个词中间时，照样剪，但回执里给出警告，因为这样的剪点听得出来。余量取多少、接点要不要加几毫秒的淡变，待试验。

## 5. 稿子

提交之后的稿子是这样的：

```
<!-- columbina story: talk · 3f9a61c2 -->

## interview.mp4

[a1 00:01] 大家好，~~呃~~ 今天聊一聊怎么剪视频。
[a2 00:06] ~~这个这个~~ 这个工具可以按文字来剪。
  > 画面 screen.mp4 盖住“按文字来剪”
[pause 1.8s]
[a3 00:12] ~~我们先看，不对，我重说一遍。~~
[a4 00:17] 我们先看一个例子。
```

规则不多：

- 一行是一句。方括号里是这一句的编号和它在原素材里的时间。时间只是给人看的，改它没有用。
- 删掉一行，这句话就剪掉。把词划掉或者直接删掉，这些词就剪掉。提交之后重新生成的稿子里，剪掉的句子和词都还在，带着划线。把划线去掉，它们就回来。
- 把一行挪到别处，这句话就挪过去。
- `[pause]` 一行是一处长停顿。把数字改小就缩短，删掉这一行就缩到默认的最短间隔。
- 以 `>` 开头的缩进行是挂件的说明，只读。
- 留下的词不许改字。稿子里的字对应的是录下来的声音，改字不会让人说出别的话。错别字用另一个工具改。
- 认不出来的行是错误，不会被悄悄忽略。

**为什么是一个文件。** 模型已经会读文件、改文件、在文件里搜索，这些工具有权限、有读后才写的规矩、有输出上限，都是现成的。在一小时的口播里找所有的“然后呢”，一次 `grep` 就够。人可以用任何编辑器改同一个文件。两次提交之间稿子的差异，就是这次剪了什么。

**稿子和时间线的关系，像工作区和提交。** 时间线是定下来的状态，稿子是正在改的那一份。提交工具把稿子读进来，逐行对上原来的词，算出新的主线，写进时间线，再把稿子按新的状态重新生成。稿子开头那串字符是它生成时时间线的摘要，时间线在别处变过，稿子就过期了，提交会被拒绝，并说明怎样拿到新的稿子。

**对词的规则。** 每一行只在这一行自己的词里对。划掉的词要和原词逐个对上。直接删掉的词，如果有重复的词而分不清删的是哪一个，取靠后的保留，也就是剪掉先说的那一遍，这是“呃我我我觉得”这类重复最自然的剪法。行里出现了原来没有的词，或者词序变了，这一行报错，整次提交不生效，回执里写明是哪一行、哪里对不上。对的时候只看字母、数字和汉字，不看标点、空格和大小写。

**提交是整批生效或者整批不生效。** 回执写明剪了几句、几个词，成片时长从多少变成多少，哪些挂件没处挂了，哪些剪点落在连着说的词中间。可以只算不提交，先看回执。

## 6. 给模型的工具

| 工具 | 做什么 |
|---|---|
| `video_import` | 把文件登记成素材。工程不存在时建立，画幅和帧率取第一个视频素材的 |
| `video_transcribe` | 转写一个素材。按素材的身份记账，转写过的直接返回，中断的可以接着做 |
| `video_apply` | 核对稿子并提交，可以只算不提交，可以带“停顿最长留多少” |
| `video_correct` | 改正转写里的错字。只改显示的文字，不动时间 |
| `video_overlay` | 加、改、删挂件和标题，设转场，开关字幕和配乐的自动压低 |
| `video_render` | 渲染预览或成片，可以只渲染一段 |
| `video_undo` | 撤销或者重做最近的提交 |
| `video_info` | 工程的现状：素材、转写的进度、成片时长、挂件、最近的输出 |

一共八个。读稿子用 `read`，搜索用 `grep`，改稿子用 `edit`，不另设工具。挂件挂在哪里，用“哪一行的哪几个词”来说，和 `edit` 找文字的规矩一样：给出的文字在那一行里必须正好出现一次。

这一版不给模型看画面。它凭文件名、时长、转写和场景切换点来选画面。给能看图的模型抽帧，或者让另一个模型把画面描述成文字，留作后续，抽帧的函数在 `media` 里先做好。

给人用的命令是同一套函数，一个人不经模型也能走完全程：

```
columbina video import talk raw/interview.mp4 raw/screen.mp4 music.mp3
columbina video transcribe talk
（用任何编辑器改 talk/story.md）
columbina video apply talk
columbina video render talk --preview
```

转写出来的文字是从文件里读到的东西，不是用户的要求。视频里有人说“忽略之前的指示”，那也只是一句台词。稿子是经 `read` 读到的文件内容，和别的文件一样按主设计文档 9.6 节对待。

## 7. 渲染

渲染是一个纯函数加一次运行：把时间线、范围和档位编译成一条 ffmpeg 命令，运行它，输出先写到临时文件，成功并且查过之后才改名到 `out/`。

- 主线：同一个素材里顺着时间往后的若干段，在一次解码里选出来。调过先后的部分各算一路输入，最后接起来。
- 挂件：每个一路输入，按属性裁切缩放，在它的时间段里叠到主线的画面上。
- 声音：主线的人声、挂件自己的声音、配乐混在一起。配乐用人声做旁链压低，最后可以统一响度。
- 标题和字幕：生成一个字幕样式文件，最后一步烧进画面。也可以不烧，只导出 `.srt`。
- 档位：预览是低分辨率加最快的编码；成片是高质量的 H.264 和 AAC，有 NVENC 时可以选用。

渲染完做三样检查：输出文件的时长和时间线差不超过一帧，画面和声音两路都在，文件不是空的。检查不过算失败，`out/` 里不留半成品。

一小时素材剪出三百个剪点时这条命令有多长、跑多久、占多少内存，待试验。撑不住就改成分段渲染再拼接，分段的结果按内容缓存，改一处只重做一段。

## 8. 转写

接缝很小：给一个音频文件和可选的语种，交回逐词的转写，途中报告进度。程序先用 ffmpeg 把素材的音轨抽成 16 kHz 单声道，再交给提供者。

本机的提供者在另一个进程里运行。模型加载在那个进程里，主进程不引入这批依赖；转写崩了或者被取消，杀掉那个进程就干净了，这也是现成的。两个进程之间逐行传 JSON，已经出来的句子随时落盘，所以中断之后能接着做。

模型文件不小，从几十 MB 到一两个 GB。程序不替用户下载：缺模型时工具报错并写明下载的命令，下载是用户自己执行的一步。缺省在有 GPU 时用最大的那一档，没有时用小的。

测试用假的提供者，按脚本吐词。真的提供者有一条可选的测试：用系统自带的语音把一段已知的文字念出来，转写后和原文比，机器上没有模型时跳过。

逐词时间准不准，中文里一个“词”有多大，简体繁体会不会混，都待试验。

## 9. 撤销

每次提交之前，旧的时间线存进 `history/`，带上是哪个会话的哪次调用、回执的第一行。撤销就是把上一份拿回来当作一次新的提交，重做同理。转写和素材不变，所以存时间线就够了，一份不过几百 KB。保留最近的两百份。

提交要写三个文件，顺序是：旧时间线存进历史，新时间线替换旧的，稿子重新生成。每一步都是先写临时文件再改名。中途断电最坏的情形是时间线已经是新的而稿子还是旧的，这时稿子的摘要对不上，下一次使用时发现；稿子没有被人改过就直接重新生成，被改过就照“过期”处理。

补强计划里记着“撤回一轮的文件修改”这件事。它做出来之后，回到某一轮之前的状态会连同工程目录一起回去，和这里的撤销不冲突：这里按提交撤，那里按轮撤。

## 10. 安全

- ffmpeg 程序的可信：和容器沙箱里找 `docker` 程序一样，从名字到文件逐段走，任何一步落在工作目录里都不用。
- 参数从不经过 shell。
- 媒体文件是不可信的输入。有些格式其实是一张清单，会让 ffmpeg 去读别的文件或者连网络。只允许本地文件这一种协议挡不住它：清单指向工程之外的文件时，走的也是本地文件协议，试验七里就这样读到了。挡得住的是格式的白名单。所以凡是对外来的文件调用 ffprobe 和 ffmpeg，协议的白名单和格式的白名单都加上。ffprobe 报出的格式还要和程序自己的一张表对一遍，不在表里的在导入时拒绝，以防旧版本的 ffmpeg 不认其中某个选项。
- 标题的文字、字幕和文件路径不拼进滤镜的参数里，都写进文件再让 ffmpeg 去读。样式文件用程序自己起的名字，放在为这一次渲染新建的目录里，ffmpeg 就在那个目录里运行，滤镜的参数里只出现这个文件名。试验五里完整路径怎样转义都没有成功，只写文件名是成功的。
- 工程目录之外不写任何东西。素材只读。

## 11. 测试

- 纯函数：稿子的生成与解析互为逆运算、对词、从词到片段、挂件的定位、编译出的参数。大量的属性测试，新增的行为各有变异体。
- 用 ffmpeg 的测试：素材现场生成。每个素材是一种纯色配一个固定频率的单音，渲染之后抽帧看颜色、取一小段声音看频率，就知道某一刻出来的是哪个素材的哪一段，剪点差一帧也看得出来。不需要人眼，也不需要会看图的模型。
- 机器上没有 ffmpeg 时这些测试跳过；设了 `COLUMBINA_REQUIRE_FFMPEG=1` 时算失败，和容器的测试一个规矩。持续集成里装不装 ffmpeg，要作者同意才改。
- 端到端：脚本化的模型经 `columbina run` 走完导入、转写（假的提供者）、改稿子、提交、挂画面、渲染，核对输出。
- 真实服务：DeepSeek 对一段真实的口播做一次粗剪，手动运行。

## 13. 先做的试验

写实施计划之前要在本机弄清楚的事。本机是 Windows 11，ffmpeg 8.1.1 的完整构建，RTX 4080。

1. 逐词时间有多准。用系统语音念一段已知的中文和英文，转写后逐词比对，量出词首词尾的误差，定余量取多少。
2. 按词剪出来听起来怎样。剪点要不要加几毫秒的淡变，画面和声音会不会错开。
3. 一条命令撑得住多少个剪点。三百个、一千个剪点各试一次，量时间和内存。
4. 手机录的可变帧率素材、带旋转标记的素材，导入和渲染对不对。
5. 字幕样式文件的路径在 Windows 上怎样写才不出错，中文字体怎样选。已做。
6. 旁链压低配乐的参数取多少听着自然。
7. 清单类的格式能不能被“只许本地文件”挡住。已做。

第 5 项和第 7 项不用下载任何东西，2026-10-14 做完了，结论已经写进第 10 节和第 14 节。其余五项还没有做：第 1 项要下载转写模型，等作者同意；第 2 项和第 6 项要人听；第 3 项占机器，等没有别的任务在跑的时候做；第 4 项要一段手机录的素材。

试验五。把样式文件烧进两秒钟的纯色画面，工程目录的名字里有中文、空格、逗号、单引号和方括号。样式文件只写文件名、ffmpeg 在它所在的目录里运行时成功。写完整路径时失败，盘符后面的冒号被当成滤镜选项的分隔符，按两层转义的规则转义之后仍然失败。字体方面，指定微软雅黑或黑体时用的就是它。指定没有中文的 Arial，或者一个不存在的字体名时，字幕库自己换了一款有中文的字体，画出来的仍是中文。Linux 和 macOS 上没有试：那里的字体不同，字幕库会不会自己找也取决于 ffmpeg 是怎样构建的。

试验七。七个清单类的文件，分别不加选项、只许本地文件协议、只许几种格式、两者都加，交给 ffprobe，一共 28 次，本机上有一个监听的端口数有没有人来连。没有一次连出去。但是只许本地文件协议时有两个文件被读了：一个名字以 `.m3u8` 结尾的清单读到了工程之外的文件，一个 concat 清单读到了它旁边的文件，两者走的都是本地文件协议。加上格式的白名单之后，七个文件全部在打开它们指向的东西之前失败，真正的媒体文件照常读出。没有试的有 DASH、SDP、按引用指向别的文件的 QuickTime 文件，以及引用字体或图片的字幕。

## 14. 风险

| 风险 | 打算 |
|---|---|
| 逐词时间不够准，剪点吃字 | 试验一和二定余量；回执里标出可疑的剪点；实在不准时在提供者里加一步对齐 |
| 一条 ffmpeg 命令撑不住长片 | 分段渲染加拼接 |
| GPU 的运行库在 Windows 上难装 | 提供者自己检查，装不上时退回 CPU 和小模型，并说清楚 |
| 模型把稿子改乱 | 解析从严，报错到行；提交整批生效或不生效；每次提交可撤销 |
| 素材被移动或者换掉 | 导入时记身份，用之前核对，对不上时说明，不拿错的文件去渲染 |
| 高动态范围和 10 位色深的素材 | 这一版不处理色彩转换，导入时警告 |
| 字幕里的中文缺字 | Windows 上字幕库会自己换一款有中文的字体，试验五看到了。仍然指定一款有中文的字体，让不同机器上画出来的一样。Linux 和 macOS 上待试验 |
