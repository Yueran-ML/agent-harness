# 桌面端 0.1.1：输入框里的模型选择

用户 2026-10-15 定的三件事：先发布 0.1.0，这个功能进 0.1.1；按钮放在输入框左下角；选了就记成这个服务的默认模型，下次启动也用它。

## 做什么

- 输入框底部一行的左边加一个按钮，写着当前的模型，例如 `deepseek-flash`。悬停提示写出服务和模型。
- 点开是一个向上展开的列表：
  - 顶上写服务名，旁边一个“重新获取”。
  - 一个过滤框，打开时键盘就在这里，打字即过滤。
  - 服务实际提供的全部模型，按服务给的顺序；当前的模型打勾。
  - 底部一项“设置服务或密钥”，打开密钥窗口。
- 过滤：不分大小写的子串匹配。完全相同的排第一，以它开头的排其次，其余按原顺序。
- 过滤框里写的不在列表里时，第一项是“使用 “…””，这样服务没列出或列不出来时，仍能手写模型名。像密钥的文字（`looksLikeAKey`）不给这一项，免得把密钥当模型名明文存下来。
- 键盘：上下键移动，Enter 选中，Esc 关闭并把键盘还给按钮。点列表外面也关闭。
- 状态：
  - 正在获取：月亮加“正在向 DeepSeek 获取模型列表”。
  - 失败：按 `setup --check` 的 `kind` 说原因。本机服务没运行时用密钥窗口的 `notRunning` 那几句。下面给“再试一次”。
  - 列表为空：说服务没有列出模型。
  - 过滤后没有匹配：说没有匹配的模型。
- 有回合在进行、正在启动或正在发送时，列表照常显示，但不能选，并说明要等 Columbina 空闲。回放里没有服务程序，只说明这里看不到模型列表。
- 设置里“模型”那一栏的手填框和“应用”按钮，换成同一个选择器（向下展开）。

## 怎么做

- **列模型**：`columbina setup --check` 收到不带 `api_key` 的文档时，会像会话一样去环境变量和已存的密钥里找密钥，答 `{"models": [...]}` 或 `{"error", "kind"}`。外壳给主窗口加 `columbina:models`，只传服务名；名字必须在主窗口最近一次 `--list` 的答案里。密钥始终不经过页面。
- **记住**：外壳给主窗口加 `columbina:choose-model`，只传服务名和模型名，经标准输入交给 `setup --from-stdin`。不带密钥，所以已存的密钥保持不动。模型名不能为空，最长 200 个字符，不能有看不见的字符和空白。
- **立刻生效**：页面向服务进程发 `/model <名字>`（不写进对话），和设置里现在的做法一样。成功后重新读一遍服务列表。
- 列的是**服务进程正在用的那个服务**（`status.model.provider`）的模型，因为 `/model` 只作用于正在运行的进程。如果用户在密钥窗口里选了另一个服务、还没重启，这时只切换不存，免得 `--from-stdin` 把“正在用的服务”改回去。
- 列表按服务缓存在页面里。打开时如果没有缓存、上次失败了，或者已经过了五分钟，就重新获取。同一服务同时只问一次，晚到的旧答案不算数。
